# SirTone («Сиртон») — правила для Claude Code

Локальный музыкальный плеер для Windows 10/11. Студия: Серков Studio. Стек: **Tauri 2 (Rust-ядро) + WebView2 (React 19/TS/Vite/Tailwind 4/shadcn)**. Версия спецификации: **1.3** (2026-10-16) — включает дополнение владельца «Умная волна, сезоны, события и режимы».

## Главные принципы владельца

1. **Не изобретать — копировать.** Для любой фишки сначала смотри `docs/01a_*.md` / `docs/01b_*.md` / `docs/01c_*.md` (как это делают 6+ популярных приложений), потом адаптируй. Нет референса — найди (документация, SDK, справка), запиши в `docs/01*` и только потом реализуй. Особенно: автомикс, визуализация, архитектура, движок волны.
2. **Спецификация — закон:** `docs/02_TZ.md` (нормативно, ID `FR-*`; волна и режимы — §26), детали — `03`…`09` и `14`. Отклонение = новая запись в `docs/10_DECISIONS.md`. Открытые вопросы владельцу — `10` §5 (Q-1…Q-17): до ответа действует предложенное там.
3. **Визуал даёт владелец** (шрифты, цвета, макеты, стиль анимаций, палитры сезонных тем, вид эффектов). Не придумывать дизайн: нейтральный каркас + токены (`docs/06` §1). Ни одного захардкоженного цвета/радиуса/шрифта/длительности в компонентах.
4. **Скорость и лёгкость:** отклик ≤ 400 мс (цель p95 ≤ 100), всё тяжёлое отключаемо пресетами, бюджеты — `docs/08` §1 (в т.ч. пересборка волны ≤ 15 мс).
5. **Данные пользователя неприкосновенны:** аудио не перекодируется и не изменяется; файловые операции — только через журнал (`fs_journal`); удаление — только в Корзину; нет уверенности в распознавании → «Неизвестные», а не неверная папка. Журнал прослушиваний и модели вкуса — только локально.

## Среда и команды (Windows PowerShell 5.1)

Тулчейн на D:\DevTools (Rust 1.99, MSVC, pnpm 12, cargo-deny, cargo-nextest). В «старой» оболочке: `. .\scripts\dev-env.ps1`. `pwsh` локально не установлен. После появления каркаса:

```powershell
pnpm install; pnpm tauri dev
cargo nextest run --workspace --no-tests=warn
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all -- --check
cargo deny check
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\check-all.ps1   # всё сразу (Bypass — только для процесса)
```

Прототипы спайков — `spikes/S-NN-*/` (вне workspace, свой `cargo test --release`). Диск C: почти полон — кэши и `target` держим на D:. Подробности — `docs/11_DEV_ENV.md`.

## Правила кода

- **Rust:** workspace `crates/sirtone-*` (`core, net, library, recognize, analysis, search, audio, playback, platform, wave, cli`) + `apps/desktop/src-tauri` (единственный, кто знает Tauri). Зависимости между доменными крейтами запрещены (только через трейты `core`: `WaveRepo`, `QueueSource`, `PlaybackControl` и т.п.). `unwrap()/expect()` — только в тестах и инициализации. Ошибки: `thiserror` в крейтах, `AppError{code,retryable,details}` на границе IPC; **тексты для пользователя формирует UI по коду**.
- **Аудио-поток (RT):** никаких аллокаций, мьютексов, логов, ввода-вывода; метрики — атомики; `catch_unwind` вокруг декодеров. Тяжёлое — в потоке движка; в колбэке только копирование и «поздние» множители (громкость, приглушение, сон-фейд, пауза-фейд).
- **Движок волны:** время только из `Clock` (подменяемые часы — для тестов сезонов и событий); веса, пороги, словари, календарь, палитры — в `assets/wave/*.json`, не в коде; горячий путь скоринга без аллокаций; всё объяснимо через `explain`.
- **IPC:** типы генерируются из Rust (tauri-specta/ts-rs — ADR D-09); ручные TS-типы IPC запрещены; события асинхронные и батчатся; бинарные потоки — `Channel`; картинки — только через протокол `sirtone-cover://`.
- **БД:** `rusqlite` + миграции вперёд; только параметры/белый список полей; пути относительные корню библиотеки.
- **Фронтенд:** feature-sliced (`docs/03` §3.2); вызовы `invoke` только в `shared/ipc`; **ни одной строки в JSX** (i18n-ключи, русские формы one/few/many); не обновлять CSS-переменные корня чаще 4 Гц (высокочастотное — canvas/WebGL; смена темы — одно присваивание `@property`-цветов); анимации только `transform/opacity`; эффекты уважают `prefers-reduced-motion`, вспышки ≤ 1 за 10 с.
- **Лицензии:** без GPL/AGPL/CC-NC в бинарнике (`docs/08` §3); Essentia-модели не используем; новые зависимости — только через `cargo deny`/реестр `docs/08` §5. Из GPL-проектов (Mixxx, Picard, Navidrome, WaveFlow, bliss) берём **идеи, не код**.
- **Сеть:** только перечисленные хосты (`docs/08` §4), лимитеры (AcoustID ≤ 2/с, MusicBrainz ≤ 0,8/с, ListenBrainz ≤ 1/с, описательный User-Agent), мастер-тумблер офлайн; телеметрии нет.

## Работа с git и релизами

- Репозиторий локальный. **Владелец разрешил локальный коммит после каждой готовой задачи (D-36); push — запрещён** до отдельной команды и настройки GitHub (OWN-04). Ветка этапа `stage/N-<имя>`, слияние в `main` после приёмки этапа. Релиз («собрать билд и опубликовать» ✅) — по команде владельца: `scripts/release.ps1` → тег → GitHub Actions (нужны OWN-01/04).
- Идентификатор приложения — `studio.serkov.sirtone` (D-37), менять нельзя.
- Сообщения коммитов — Conventional Commits; не пропускать хуки.

## Чего не делать

Не добавлять функции вне ТЗ (список «вне скоупа» — `docs/02` §23): стриминги, тексты песен, раздел «История» в интерфейсе (внутренний журнал для обучения — можно), синхронизация, профили, бэкап, импорт m3u, перекодирование, системные уведомления (события — только карточки в приложении), анкета вкуса. Не утверждать, что фича «как у X», если это не записано в `docs/01*` с источником. Не менять настройки безопасности Windows (Defender, SAC, политику выполнения скриптов) без явного разрешения. Действия «выключить экран/усыпить ПК» — только по явной настройке пользователя.
