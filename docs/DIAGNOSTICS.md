# Диагностика SirTone

Статус: Windows foundation D-180. Формат и экспорт работают локально; отправка Feedback API и iOS-часть ещё не реализованы.

## Принципы

- Диагностика не является телеметрией: без явного выбора «Сохранить отчёт» ничего не передаётся.
- Installation ID — случайный UUID для этой установки; Session ID — новый UUID на каждый запуск; Report ID — UUID каждого ZIP.
- Не используются MAC-адрес, serial number, Apple ID или аппаратный fingerprint.
- Незакрытый маркер прошлой сессии означает только отсутствие штатного выхода. Это не утверждение о crash.
- Любая запись JSONL выполняется вне audio RT-path. В callback аудио запрещены файловые операции, mutex, форматирование и аллокации.

## Что хранится локально

`%LOCALAPPDATA%\SirTone\diagnostics` (или portable/Test data-dir) содержит Installation ID, маркер сессии и JSONL-файлы `events-YYYY-MM-DD.jsonl`.

Разрешённые поля события: версия схемы, UTC-время, уровень, event ID, Session ID, платформа, версия/Build ID, канал, компонент, операция, код ошибки, безопасный контекст и recoverable. Контекст имеет allow-list: попытка, тип аудиоустройства, тип ошибки, состояние сети/операции, задержка повтора. Значения приводятся к коротким техническим атомам.

Срок обычных событий — до 7 дней; общий объём — до 10 МБ. Повреждённые строки JSONL пропускаются при экспорте.

В события и экспорт не попадают музыка, база медиатеки, имена треков, полные пути, история, предпочтения, Apple ID, пароли, токены и HTTP authorization headers.

## Экспорт отчёта

В Windows: «Настройки» → «Помощь и диагностика» → «Сохранить отчёт». Файл создаётся локально в `reports` data-dir с именем `sirtone-report-<Report ID>.zip` и не превышает 5 МБ.

ZIP содержит:

- `summary.txt` — короткое резюме;
- `manifest.json` — версия формата и идентификаторы;
- `environment.json` — ОС и архитектура;
- `events.jsonl` — события последних 24 часов;
- `errors.json` — ошибки из выбранного окна событий;
- `README.txt` — ограничения состава.

При превышении лимита сохраняются более новые события, а manifest/summary помечают усечение. В текущей реализации архив не отправляется автоматически и не распаковывает недоверенные ZIP.

## Разработчику

Автоматические тесты `diagnostics` проверяют идентификаторы, маркер сессии, ротацию, повреждённый JSONL, состав ZIP и отсутствие подставленных пути/токена. Уровень developer logging по-прежнему задаётся `SIRTONE_LOG`; он не меняет allow-list экспортируемых событий.

Чтобы удалить локальные диагностические данные, закройте SirTone и удалите только папку `diagnostics` в data-dir. Это создаст новый Installation ID при следующем запуске; музыка и база медиатеки не затрагиваются.
