# Спайк S-17 — скоринг движка волны на синтетической медиатеке

- **Дата / сессия:** 2026-10-16, сессия доработок (спецификация 1.3), до Этапа 0
- **Связанные требования:** FR-WENG-001…009, FR-NOV-001…004, FR-SEAS-001, FR-EVT-001, NFR-PERF-004 · **ADR:** D-38, D-39, D-42, D-43, D-44
- **Референсы (`01*`):** `01c` W-03 (YouTube two-stage, Spotify/Deezer бандиты, Chapelle & Li), W-10 (квоты ползунка), §12 (даты)

## 1. Вопрос и критерии (дополнение владельца §36, «до кода»)
- Успех: пересборка очереди на 50 000 треков по матрице в памяти **< 15 мс**; обновление модели после события — «микросекунды»; квоты ползунка выдерживаются; Пасха/Масленица 2027–2030 считаются офлайн без ошибок.
- Отказ → план Б: уменьшить кандидатов SQL-префильтром до ≤ 10 000, параллелить этап 1 (rayon), упростить модель вкуса до таблицы по кластерам.

## 2. Что сделано
Код: `spikes/S-17-wave-scoring/` (Rust 2024, без внешних зависимостей, `cargo run --release -- 50000 300`, тесты — `cargo test --release`).
- Синтетическая медиатека: 32 признака на трек с реалистичными корреляциями (энергия ↔ темп/танцевальность, позитив ↔ мажор), 5 000 исполнителей с перекосом, история прослушиваний (40 % нетронутых), лайки, «никогда» (0,2 %), сезонные аффинности, популярность (лог-нормальное число слушателей).
- Этап 1: все 9 компонентов профиля (вкус = логистическая регрессия + бета-среднее, контекст, сессия, сезон, событие, кривая, универсальность, мягкий фильтр, «непохожесть») → топ-64 в каждой из трёх групп знакомости.
- Этап 2: выбор группы по отставанию от квоты, Томпсон по бете трека, разнос исполнителей (5), окно повтора (24 ч), плавность энергии (≤ 0,35), бонус перехода (темп ±8 %), softmax по топ-20 (T = 0,05).
- Модель вкуса: диагональная байесовская логистическая регрессия (Chapelle & Li 2011), сэмплирование весов на пересборку.
- Календарь: даты (Хиннант), Пасха (Meeus/Jones/Butcher, юлианская Меёса + 13/14 дней), Масленица, смесь сезонов с окном, поправка погодой, средние формулы равноденствий/солнцестояний (Меёс, гл. 27).

Окружение: Windows 11 10.0.26300, AMD Ryzen 7 5800H (8C/16T), Rust 1.99.0, профиль release (`lto = "thin"`, `codegen-units = 1`), без rayon.

## 4. Наблюдения и сюрпризы
- Запас по скорости ×5 на 50 000 треков: пересборку можно делать синхронно в потоке `wave-worker`, без пула и без SQL-сужения кандидатов (SQL оставляем только для жёстких фильтров по индексам).
- Главная стоимость — скалярные `exp`/`tanh` в сигмоидах; при необходимости их можно аппроксимировать — пока не нужно.
- Числа окна сезонов в дополнении противоречат собственному примеру → предложено окно ±21 день (Q-10).
- Синтетика не заменяет качество: веса и пороги калибруются на реальной медиатеке владельца (OWN-08), прототип подтверждает только скорость и корректность механики.

## 5. Решение
Принято: двухступенчатая схема (этап 1 по всей матрице в памяти → топ-K по группам → секвенсор), модель «бета по треку + байесовская логистическая регрессия + Томпсон» (D-39), квоты ползунка в секвенсоре (D-42), календарь без сети (D-43). Записи — `10_DECISIONS.md`.
