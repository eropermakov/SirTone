# Спайк S-01 — вывод звука: WASAPI shared, event-driven

- **Дата:** 2026-10-16, Этап 0 (путь к прототипу 0.2)
- **Связанные требования:** FR-PLAY-001/004/005/012, NFR-AUD-001 · **ADR:** D-05 · **Задачи:** T0.15, T1.1, T1.3
- **Вопрос (`09` §4):** держит ли `wasapi` 0.26 вывод без провалов под полной нагрузкой CPU; как проверить звук без ушей (владелец работает удалённо).

## 1. Что сделано
Код: `spikes/S-01-output/` (вне workspace). Архитектура — как в `04` §1: поток движка (symphonia → раскладка каналов → `rubato` FFT-ресемплер к частоте микс-формата → кольцо `rtrb` 200 мс) и RT-поток вывода (MMCSS «Pro Audio», ожидание события устройства, копирование из кольца × атомарное усиление, без аллокаций/блокировок/логов).

**Проверка без ушей:** приложение записывает **собственный звук** через *application loopback* WASAPI (`AudioClient::new_application_loopback_client(pid)`) и анализирует запись: уровень, «дыры» тишины по 10 мс, флаги `DATA_DISCONTINUITY`, мощность 440/660 Гц отдельно в левом и правом канале (Гёрцель). Плюс счётчик underrun в RT-цикле.

Устройство: «Динамики (Senary Audio)», микс-формат 48 кГц / 2 к / float32, период 10,7 мс (мин. 3,0), буфер 1126 кадров. Ryzen 7 5800H 8C/16T, Windows 11 10.0.26300.

## 3. Выводы
- **D-05 подтверждено:** `wasapi` 0.26 (shared, event-driven, MMCSS) — основной вывод; `cpal` не нужен. Нагрузка RT-цикла ≈ 0,3 % периода.
- Микс-формат почти всегда 48 кГц float → ресемплинг обязателен для 44,1 кГц (сделан, высота тона подтверждена).
- Self-loopback — штатный способ автоматической проверки звука (для CI-харнесса T1.7 и «тракта сигнала»).

## 4. Нужны руки владельца (не блокирует 0.2)
- Exclusive mode 16/24/32 бит 44,1–192 кГц на его устройствах.
- Смена устройства по умолчанию и выдёргивание наушников/BT (T1.6) — сейчас при потере устройства движок ставит паузу и сообщает `DeviceUnavailable`; «Играть» переоткрывает устройство на той же позиции.
- 30-минутный и 24-часовой прогоны (сейчас 3 мин под полной нагрузкой).
