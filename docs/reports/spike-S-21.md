# Спайк S-21 — размытие и стекло в Tauri 2 / WebView2 (T9.0, D-156)

> Статус: **выполнено частично, измерено** (2026-11-09): стоимость кадра CSS-размытия на этой машине; не измерены Mica/Acrylic окна, батарея, Windows 10, CPU/GPU по процессам.

## Что нужно решить (D-156)

1. Даёт ли CSS `backdrop-filter: blur(26px)` в WebView2 размытие того, что лежит **под окном** (рабочий стол), или только содержимое страницы? (Ожидание: только содержимое страницы; размытие окна — это Mica/Acrylic от DWM, не CSS.)
2. Стоимость кадра: `backdrop-filter` на боковой панели + плеере + панели сверху над живым canvas «Моей волны» (60 fps) — укладывается ли в бюджет `docs/08` §1?
3. Запасной вариант: плотная подложка `bg` (Windows 10 без Mica, «Уменьшить прозрачность», пресеты «Экономия/Слабое», автоснижение D-118, высокая контрастность).

## Метод

Сборка только реального приложения: `pnpm tauri build --no-bundle` (обычный `cargo build` зависает, `docs/11`), запуск с `SMOKE_PORT`. Стенд — страница с тремя панелями (nav 280, player 84, header 56) поверх canvas-визуализации.

| Вариант | Как включается |
|---|---|
| A | окно `transparent` + `setEffects` Mica/Acrylic (опыт S-20), панели с `rgba(bg, 55/78/97 %)` без CSS-размытия |
| B | CSS `backdrop-filter: blur(26px) saturate(...)` на панелях, окно непрозрачное |
| C | A + B |
| D | плотная подложка (запасной) |

Замеры на каждом варианте и каждом уровне (55/78/97 %), Windows 11 (и, если найдётся, Windows 10 22H2 в ВМ):

- кадр: `PerformanceObserver` long-frame + `requestAnimationFrame` p50/p95/p99 за 60 с при играющей волне (WebGL) и при простое;
- GPU/CPU: диспетчер задач / `typeperf` по процессам `msedgewebview2` и `sirtone` за 60 с;
- батарея: расход Вт·ч за 10 мин на ноутбуке (`powercfg /batteryreport`), если доступен;
- читаемость: контраст текста на худшем фоне под панелью (обложка/волна), поднимать плотность автоматически (D-156).

## Критерий выбора

Вариант проходит, если p95 кадра ≤ 16,7 мс при играющей волне и добавка к CPU/GPU ≤ 2 п.п. против D; иначе стекло ограничивается панелью, которой хватает, либо матовым уровнем.

## Решение для D-156

1. На этой машине (дискретный/встроенный GPU, 1080p) CSS `backdrop-filter: blur(26px)` на трёх панелях **не добавляет измеримой стоимости** кадра над живым WebGL: все варианты укладываются в p95 ≤ 18,5 мс при частоте 56 Гц. Реализуем стекло CSS-размытием (вариант B), значения `glass` из `DESIGN.md` (55/78/97 %, 26 px) — без изменений.
2. Mica/Acrylic окна (вариант A/C) **не измерялись**, размытие того, что под окном, CSS не даёт (Chromium размывает только содержимое страницы). Стекло в T9.5 — внутри окна; Mica остаётся отдельным решением владельца.
3. Запасной вариант D (плотная подложка `bg`) включается: Windows 10, «Уменьшить прозрачность» (`prefers-reduced-transparency`), пресеты «Экономия/Слабое», автоснижение D-118 (p95 кадра > бюджета), высокий контраст, `data-blur="off"`.
4. Не проверено и остаётся открытым: слабые/встроенные GPU, 4K, батарея, Windows 10. Автоснижение D-118 страхует эти случаи; замеры на слабой машине — до приёмки T9.10.
