# Проверка П4б — установка по Wi-Fi через RemotePairing

- **Дата / сессия:** 2026-11-07, ветка `stage/8-mobile`, прототип `spikes/S-P4-isideload` (команды `rsd-usb`, `rp-pair`, `rp-find`, `rp-wifi`) и хаб (`sirtone-devicelink::wifi`)
- **Связанные требования:** FR-HUB-001…004, MR §6.1 шаг 10 · **ADR:** D-132, D-139, D-143 · продолжение `spike-P-04.md`
- **Референсы (`01d`):** idevice tools [M8a] — `remotepairing_lockdown.rs`, `pair_rsd_ios.rs`, `rppairing.rs`; isideload `install_app_rsd` [M7]
- **Статус:** 🟡 код готов и собран, **на iPhone ещё не проверен** (телефон не был на кабеле)

## 1. Вопрос и критерии
- Почему нужна: в П4 по Wi-Fi служба Apple телефон не видит, а iOS 27 рвёт AFC через сетевой lockdown. Телефон в анонсе Bonjour пишет `supportsRP-24`, то есть по сети работает RemotePairing.
- Успех: по кабелю один раз создаётся запись RPPairing без запросов на телефоне; дальше по Wi-Fi (экран включён, та же сеть) хаб находит телефон, открывает туннель и ставит приложение без пароля. Файлы приложения при этом сохраняются.
- Отказ → план Б: только кабель, в мастере подсказка «подключите кабель для продления».

## 2. Что сделано (цепочка — как в idevice tools, не своя)
1. **Запись RPPairing, один раз по кабелю.** Служба `com.apple.dt.remotepairingdeviced.lockdown`: на доверенном кабеле запросов нет, PIN `000000`. Запись содержит закрытый ключ Ed25519, поэтому хранится только в диспетчере учётных данных Windows (`studio.serkov.sirtone.rppairing`, ключ — UDID). Имя ПК для телефона постоянное — `SirTone-PC`: от него зависит идентификатор, и при смене имени на телефоне появилась бы вторая запись.
2. **Поиск.** Bonjour `_remotepairing._tcp` через системный DNS-SD Windows (`DnsServiceBrowse` из `dnsapi.dll`, Windows 10 1809+), без новых зависимостей. Свой телефон узнаётся по `authTag` (SipHash по `alt_irk` записи), как это делает CoreDevice.
3. **Туннель.** Сначала pair-verify записью. На новое сопряжение при ошибке **не откатываемся**: сломанная запись должна быть видна как ошибка, а не всплывать запросом на телефоне. Дальше `createListener` → TLS-PSK + CDTunnel → программный TCP (jktcp) → RSD.
4. **Установка.** Делаем то же, что `Sideloader::install_app` по кабелю: регистрация устройства, подпись копии. Потом `install_app_rsd` — AFC и installation_proxy внутри туннеля.
5. **Хаб.** `apple::install` ставит по кабелю, если телефон на нём, иначе по Wi-Fi, если есть запись. Мастер после установки по кабелю включает Wi-Fi в фоне (шаг 10): ответ мастера не ждёт, ошибка установку не портит. Если телефон явно отверг запись (`PairVerifyFailed`, `PairingRejected`), она стирается, и следующая установка по кабелю делает новую. Обрыв сети запись не трогает. «Отключить телефон» стирает и запись Wi-Fi. В CLI добавлены `phone wifi-pair <udid|usb>`, `phone wifi-find` и отладочная `phone bonjour <служба>`. Спайк хранит запись там же, где хаб (`studio.serkov.sirtone.rppairing`): обе стороны представляются телефону как `SirTone-PC`, и две разные записи вытесняли бы друг друга.
6. **`rsd-usb` в спайке.** Тот же путь RSD, но по кабелю (CoreDeviceProxy). Если он не пройдёт, Wi-Fi можно не проверять: дело в установке внутри туннеля.

## 4. Наблюдения
- Без записи RPPairing телефон `_remotepairing._tcp` не анонсирует. Проверять поиск имеет смысл только после сопряжения.
- **mdns-sd на этом ПК глух**, вероятно потому, что UDP 5353 держит Bonjour от Apple (`mDNSResponder`). Системный DNS-SD Windows работает рядом с ним и уже имеет правила брандмауэра. Поиск в хабе поэтому через него.
- В анонсе адреса IPv6 link-local. В mDNS нет scope-id, поэтому подключаемся сначала по IPv4.
- Над idevice фильтр логов оставлен на `warn`: его `debug!` печатает содержимое рукопожатий.

## 5. Решение
Пока **нужна проверка на iPhone** — одна сессия с кабелем:
1. `sp4 rsd-usb <apple-id> <App.app>` — установка через RSD по кабелю;
2. `sirtone-cli phone wifi-pair usb` — запись RPPairing;
3. отключить кабель (экран включён, домашний Wi-Fi);
4. `sirtone-cli phone wifi-find` → `sp4 rp-wifi <apple-id> <udid> - <addr:port>` — туннель и RSD с диагностикой;
5. `sirtone-cli phone install <apple-id> <udid> <App.app>` — путь, который пойдёт в хаб;
6. проверить, что файлы приложения (Documents) на месте;
7. `sirtone-cli phone renew <apple-id> <udid>` во время воспроизведения — первая часть П3 (профиль ставится, звук не рвётся); полный П3 — 8 дней без переустановок (`stage-8-device-session.md`). Если пройдёт и при включённом частном адресе Wi-Fi, шаг мастера «Частный адрес Wi-Fi» (из П4) не нужен.

## 6. Последствия для бэклога
- M2.1: путь Wi-Fi в `sirtone-devicelink` готов, но **из интерфейса хаба пока недоступен**: `phones()` показывает только то, что видит служба Apple, поэтому телефон только в Wi-Fi виден лишь в CLI. После проверки — телефоны по Wi-Fi в `phones()` и карточках хаба.
- П3: `apple::renew` готов — свежий профиль App ID у Apple → `misagent` по кабелю или через туннель Wi-Fi, без переустановки (как `RefreshAppOperation` в AltStore [M11]); CLI `phone renew`. Не проверено.
- П9: та же запись RPPairing и тот же туннель, но со стороны телефона.
- Точки доступа (телефон раздаёт / ПК раздаёт) — после проверки Wi-Fi.
