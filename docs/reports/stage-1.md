## Проект импорта (T1.11–T1.14, `05` §3, `03` §15.2)
- **Трейты в `core`** (реализации подключает `app`): `MediaProbe::probe(path) → MediaInfo` (`audio`, symphonia), `TagReader::read(path) → Tags` (`recognize`, lofty — T1.15; до него — пустые теги), `Identify::identify(tags, file_name, folder) → Identity` (`recognize`, T1.16–T1.17; до него — всё в `_Unknown` с причиной `no_metadata`), `VolumeInfo` (`platform`: съёмный ли носитель, свободное место).
- **Таблица `import_item`** (новая, в `0001`, D-66): строка на исходный файл — `batch_id, src_path, size, state (discovered|copied|placed|rejected|duplicate|cancelled), staged_name, content_hash, track_id, reason`. Это даёт возобновление после убийства процесса без повторного чтения уже скопированного и честный отчёт.
- **Шаги одного файла:** проба → копия в `staging/<batch>/<n>.part` с BLAKE3 на лету → `rename` → `state=copied` → личность → дубль по `content_hash` → размещение через `fs_journal` (planned → `rename` в каноническое место или `_Unknown` → в одной транзакции: трек в БД + журнал `done` + `state=placed`) → событие «трек играбелен».
- **Восстановление при старте:** журнал `planned` без `done` откатывается (файл назад в staging), `.part` удаляются; незавершённые пакеты продолжаются с `discovered`/`copied`.
- **Параллельность:** 3 потока «проба + копия», один поток пишет в БД и размещает (SQLite — один писатель).
- Источник открывается только на чтение и не изменяется никогда; удаляются только файлы внутри `<LibraryRoot>\.sirtone\staging\`.
- **Где лежит:** `library.db`, `staging\`, `quarantine\` — в `<LibraryRoot>\.sirtone\` (`03` §8.1), staging на том же томе — атомарный `rename`. При `library.root = null` импорт отказывает кодом «нужна папка библиотеки», UI предлагает выбрать (`tauri-plugin-dialog` → через `cargo deny` и реестр `08` §5 — к прототипу 0.5).
- **Надёжность записи:** `.part` → `sync_all()` → `rename` → **повторный хэш размещённой копии** и только потом `copied` («хэши сошлись», `05` §3.2). Перемещения с `MOVEFILE_WRITE_THROUGH` и удаление в Корзину — через трейт `FileOps` (реализация в `platform`, `library` не тянет `windows`).
- **Восстановление по состоянию журнала `planned`:** есть только источник → `rolled_back`; есть только назначение, его нет в `track.rel_path` и размер совпадает → вернуть в staging; есть оба или ни одного → в `quarantine\` и в журнал, **ничего не удалять**. Итоговое имя (с суффиксом ` (2)`) вычисляется до записи `planned` и хранится в журнале; staged-файлы именуются по id строки `import_item`.
- **Причины «Не добавлено»** с самого начала: не аудио · повреждён · неподдерживаемый формат · плейлист · нет места на диске · слишком длинный путь (> 240) · ошибка чтения источника.
- До T1.15 (теги) всё уходит в `_Unknown` — поэтому T1.15 делаем **до** прототипа 0.5.
