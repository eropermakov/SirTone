## 1. Цель и схема

Сиртон на телефоне — **отдельное самостоятельное приложение**; ПК-Сиртон — **хаб**: ставит, обновляет, продлевает подпись и по кнопке переносит данные. Первым делаем iPhone; Android закладываем как готовую базу и собираем позже.

Потолок бесплатного Apple ID не обходится: подпись живёт **7 дней**, на устройстве не больше **3** таких приложений, не больше **10 App ID за неделю**. Цель — сделать продление незаметным, а не отменить его.

| Вопрос | Решение | Почему |
|---|---|---|
| Роль ПК | Хаб: установка, обновление, продление, перенос | Музыка на телефоне от ПК не зависит |
| Приложение | Своя медиатека, своя волна, свои настройки | Работает отдельно от ПК |
| Язык iPhone | Swift и SwiftUI, iOS 17+ | iPhone — эталон, нужен родной вид |
| Язык Android | Kotlin и Jetpack Compose | Родной интерфейс на том же ядре |
| Общая логика | Те же Rust-крейты через UniFFI | Один движок волны, поиска и анализа |
| Сборка iPhone | xtool в WSL (разработка), релиз — GitHub Actions (macOS-раннер) | Без Mac и бесплатно для публичного репозитория |
| Apple ID | У каждого телефона свой | Подпись не привязана к чужому аккаунту |
| Продление | Сначала хаб (волна 1), затем сам iPhone (волна 2) | Телефон перестаёт зависеть от ПК |
| Перенос | По кнопке, в обе стороны | Между переносами всё живёт отдельно |
| Выпуск | Тремя волнами | Рабочий плеер появится раньше |
| Устройства | Только телефоны | Планшеты позже |

Путь приложения: репозиторий → сборка (xtool в WSL / GitHub Actions) → неподписанный IPA в GitHub Releases → хаб в ПК-Сиртоне подписывает Apple ID владельца телефона → iPhone. Человек видит только ПК-Сиртон и телефон.

## 2. Три правила (важнее любой функции)

1. **Отдельное приложение.** Воспроизведение, импорт, анализ, поиск и волна работают на телефоне без ПК. Хаб нужен для установки, обновления и (до самопродления) продления.
2. **Справится кто угодно.** Ни одного терминала и технического слова в интерфейсе. Один экран — одно действие, картинка и понятная причина. Ошибка говорит, что сделать.
3. **Быстро, плавно, красиво.** Нарушение порогов §7 блокирует выпуск так же, как падение.

iPhone — эталон; Android повторяет бренд и логику, но ведёт себя как Android.

Навигация как в Apple Music: три вкладки и мини-плеер над ними. Сиртон отличают волна на первом экране и цвет из обложки.

| S08 | Альбом, исполнитель, плейлист | Шапка, «Слушать», «Перемешать», список | Долгое нажатие открывает меню |
| S09 | Добавить музыку | Файлы, папка, подсказка про «Файлы» и «Поделиться» | Прогресс виден на экране Медиатеки |
| S10 | Настройки | Внешний вид, Звук, Волна, Хранилище, ПК-Сиртон, О программе | Иконка в углу вкладки «Волна» |
| S11 | Срок работы | «Работает ещё 5 дней», когда продлили, как продлить | В разделе «ПК-Сиртон», без слов «сертификат» и «профиль» |

**Системные поверхности** (своего оформления нет — данные из Now Playing):

| Поверхность | Что показывает | Как сделано |
|---|---|---|
| Динамический остров | Обложка, индикатор звука, раскрытый плеер | Система берёт данные из Now Playing |
| Экран блокировки, Пункт управления | Обложка, название, управление, перемотка | `MPNowPlayingInfoCenter`, `MPRemoteCommandCenter` |
| Виджет на главном экране | Малый: обложка и Play. Средний: название, назад, Play, вперёд | WidgetKit, кнопки — App Intents (iOS 17) |
| Наушники, AirPods, AirPlay | Кнопки, смена вывода, продолжение при переключении | Команды системы, стандартная кнопка вывода |

На iPhone без острова те же данные показывает система на экране блокировки и в Пункте управления.

**`DESIGN.md` на телефоне:** токены цветов, 60–30–10, Geologica, одна Primary-кнопка на экран и законы UX — без изменений. Размеры свои: зона нажатия ≥ 44 pt; Play в мини-плеере 44, в «Сейчас играет» 72; мини-плеер 64. Заголовки по шкале токенов, но с поддержкой системного размера текста (Dynamic Type). Таб-бар системный (iOS 26 — Liquid Glass сам, iOS 17–25 — системный материал). Тактильный отклик на Play, ♡, смену трека и конец перетаскивания. VoiceOver и «Уменьшение движения» — с волны 1. Отступления от `DESIGN.md` фиксируем в `06` §12 (как для ПК).

## 5. Первый запуск и добавление музыки (FR-MOB-ONB, FR-MOB-IMP)

Пустое приложение становится плеером за минуту. Если хаб уже перенёс данные — сразу медиатека.

Первый запуск, 3 шага: (1) приветствие Sir.kov Team и одна фраза о приложении; (2) тема и цвет — по умолчанию системная тема и Sir.kov, шаг можно пропустить; (3) «Добавить музыку» или, после переноса, сводка «Перенесено 1 240 треков» и «Слушать». Разрешения — только в момент пользы (уведомления — когда есть что напомнить; геолокация — при включении погоды).

| Способ | Что делает человек | Как устроено |
|---|---|---|
| Кнопка «Добавить музыку» | Выбирает файлы или целую папку | Системный выбор, файлы копируются в хранилище |
| «Поделиться» | В Telegram, Safari или «Файлах» выбирает Сиртон | `CFBundleDocumentTypes`, без отдельного расширения и лишнего App ID |
| Папка в «Файлах» | Кладёт файлы в «Сиртон → Входящие» | `UIFileSharingEnabled` и `LSSupportsOpeningDocumentsInPlace`, разбор при открытии |

После добавления: трек можно слушать сразу, остальное доезжает фоном (прогрессивное улучшение, как на ПК). Распознавание и раскладка — немедленно, итог одной строкой «Добавлено 38, в Неизвестных 2». Мусорные файлы пропускаются молча, кодировки тегов чинятся сами. ML-анализ — порциями в открытом приложении и через `BGProcessingTask` с `requiresExternalPower` на зарядке; при нагреве и в режиме энергосбережения — пауза. Волна работает с первого трека (до анализа — по тегам и отметкам; на ПК — D-128).

## 6. Хаб в ПК-Сиртоне (FR-HUB-*)

В сайдбаре — пункт «Телефоны»; при подключении — карточка «Подключён iPhone <имя>» с одной Primary-кнопкой. Вопрос «Что установить?» задаётся после доверия: только тогда известно свободное место.

### 6.1. Мастер для нового iPhone

Каждый шаг — один экран с картинкой; хаб сам замечает выполненный шаг, «Готово» — только где проверить нельзя.

| Шаг | Что видит человек | Что делает хаб |
|---|---|---|
| 1. Нашли телефон | «Подключён iPhone <имя>» и «Установить Сиртон» | Узнаёт телефон по USB |
| 2. Компонент Apple | Только если нет: «Чтобы Windows видела iPhone, нужна бесплатная программа Apple» | Ведёт на установку iTunes и ждёт |
| 3. Доверие | Картинка: «Нажмите „Доверять“ и введите код телефона» | Ждёт сопряжения, читает модель, iOS и свободное место |
| 4. Что установить | Три карточки: «Перенести всё», «Выбрать», «Только приложение» — у каждой объём и хватит ли места | Считает объём заранее |
| 5. Выбрать | Только для «Выбрать»: «Музыка», «Плейлисты», «Вкусы и волна», «Настройки и тема» | Пересчитывает объём |
| 6. Apple ID | «Apple разрешает ставить приложения только с Apple ID. Войдите аккаунтом владельца этого телефона», затем код | Вход и сертификат этого Apple ID |
| 7. Установка | Полоса и текст: «Устанавливаю Сиртон», «Переношу 340 из 1 240 треков» | Подпись, установка, перенос |
| 8. Режим разработчика | Картинки: Настройки → Конфиденциальность и безопасность → Режим разработчика → перезагрузка | Открывает пункт в настройках телефона и ждёт перезагрузку |
| 9. Разрешить приложение | Картинки: Настройки → Основные → VPN и управление устройством → «Доверять» | Шаг только при первом Apple ID на телефоне |
| 10. Готово | «Откройте Сиртон на iPhone. Подпись будем продлевать сами» | Включает доступ по Wi-Fi и автозапуск с Windows (Q-29) |

Телефон другого человека проходит тот же мастер: на шаге 4 — «Только приложение», на шаге 6 — свой Apple ID и код со своего телефона.

### 6.2. Знакомый телефон

Хаб молча продлевает подпись; новую версию ставит сам, когда музыка не играет. Карточка: версия, срок работы, «Перенести на телефон», «Забрать с телефона», «Отключить телефон». Телефонов может быть несколько, у каждого свой Apple ID и состояние.

### 6.3. Ошибки простым языком

| Ситуация | Что видит человек | Что дальше |
|---|---|---|
| Кабель только для зарядки | «Телефон не виден. Попробуйте другой кабель» | Хаб ждёт подключения |
| iPhone заблокирован | «Разблокируйте iPhone» | Продолжит сам |
| Занято 3 приложения | «Apple разрешает 3 таких приложения, сейчас стоят: …» и список | Человек удаляет одно |
| Лимит App ID | «Apple разрешит новую установку через 4 дня» | Хаб напомнит |
| Не хватает места | «Не хватает 2,4 ГБ» и переход к выбору | Выбрать меньше |
| Apple не отвечает | «Серверы Apple не отвечают, попробуем ещё раз сами» | Повтор в фоне |
| Сеть не показывает телефон | «Эта сеть не даёт увидеть телефон. Подключите кабель или точку доступа» | «Проверить снова» |

Тексты — i18n-ключи по коду ошибки (правило проекта: тексты формирует UI по `AppError.code`).

### 6.4. Реализация (`sirtone-devicelink`, только ПК)

- Трейт `PhoneInstaller` с `IosInstaller` и пока пустым `AndroidInstaller`.
- `IosInstaller` — `isideload` + `idevice` (оба MIT); запасной путь — `plumesign` (из Impactor, MIT). SideStore, AltServer и Sideloadly рассмотрены: своего мастера не дают (и AGPL/закрыты — только идеи).
- Режим разработчика раскрывает служба `amfi` из idevice (без неё пункта в настройках может не быть, пока на телефоне нет приложения разработчика).
- Bundle ID на устройстве: `studio.serkov.sirtone.mobile.<TEAMID>`; виджет — производный ID. App Group зависит от Team ID: модуль прописывает её при подписи, приложение читает значение из Info.plist.
- Один рабочий сертификат на Apple ID; ключ хранится отдельно для каждого аккаунта (Windows Credential Manager).
- Версии `idevice` и `isideload` закреплены точно (`=x.y.z`): у idevice ломающие изменения возможны в каждом выпуске (README: «until 0.2.0»). На 2026-11-05: idevice 0.1.68, isideload 0.5.2 (у isideload не закончена работа с entitlements — README, TODO).

## 7. Скорость и плавность (FR-MOB-PERF)

Пороги — целевые значения на тестовых телефонах, для iPhone и Android; нарушение блокирует выпуск.

| Действие | Порог |
|---|---|
| Холодный старт до рабочего экрана | ≤ 1 с |
| Возврат из фона | ≤ 200 мс |
| Play, пауза, ♡, громкость, перемотка | ≤ 100 мс |
| Старт трека по нажатию | ≤ 150 мс |
| Следующий трек в волне | ≤ 100 мс |
| Переход между экранами | ≤ 400 мс |
| Результаты поиска, p95 | ≤ 80 мс |
| Новый трек можно слушать после импорта | ≤ 1 с |
| Смена цвета | старт ≤ 100 мс, перетекание 400 мс |
| Скролл списка на 10 000 треков | 99 % кадров вовремя |
| Анимации | 60 к/с, 120 на ProMotion |
| Память без визуализации | ≤ 250 МБ |

Как добиваемся: главный поток только рисует, вызовы ядра — вне него; экран сразу из локальных данных; скелетон только при ожидании > 100 мс, спиннеров нет; оптимистичный интерфейс (♡, добавление в плейлист) с тихим откатом и тостом; списки ленивые, ядро отдаёт страницами; обложки — готовые копии под каждый размер, декод вне главного потока; следующий трек открыт заранее, очередь волны всегда готова.

Как проверяем: `sirtone-cli bench` для ядра, счётчик пропущенных кадров в отладочной сборке, замер на реальном телефоне перед каждой волной; на Android — Macrobenchmark и Baseline Profiles.

| `sirtone-recognize` | Собирается целиком, сеть необязательна |
| `sirtone-audio` | Декодеры и DSP остаются, WASAPI заменён выводом платформы |
| `sirtone-net` | Те же лимитеры, хосты по функциям |
| `sirtone-platform` | Не собирается; его роль берёт платформенный слой |
| `sirtone-mobile-ffi` (новый) | Фасад UniFFI для Swift и Kotlin |
| `sirtone-transfer` (новый) | Формат пакета и слияние данных, общий для ПК и телефона |
| `sirtone-devicelink` (новый, только ПК) | Установка, подпись, продление, связь с телефоном |

Правило «доменные крейты не зависят друг от друга» сохраняется: `sirtone-mobile-ffi` — композиционный корень телефона (как `apps/desktop/src-tauri` для ПК); `sirtone-transfer` зависит только от `sirtone-core`. Склейку «пакет ⇄ медиатека» делает композиционный `sirtone-sync` (медиатека + перенос) — его используют хаб, ядро телефона и `sirtone-cli`; импорт новой музыки он получает функцией от вызывающего (свои порты платформы). `sirtone-audio`: вывод WASAPI, Media Foundation и поток движка — только Windows; декодеры и DSP собираются для телефонов.

| Папка | Что |
|---|---|
| `apps/desktop` | ПК-Сиртон и хаб |
| `apps/mobile-ios` | SwiftPM, `xtool.yml`, SwiftUI, виджет |
| `apps/mobile-android` | README и заготовка, код позже |
| `crates/` | общие крейты и новые `sirtone-*` |
| `design/tokens.json` | токены — источник для CSS, Swift, Kotlin |
| `docs/mobile/` | ТЗ, решения, Android, проверки |

- **Звук.** `AVAudioSourceNode` читает кольцо `rtrb`. Правило аудио-потока то же: без аллокаций, мьютексов, логов и ввода-вывода. Сессия `.playback`, в Info.plist `UIBackgroundModes: audio`.
- **Токены.** Значения `DESIGN.md` §13 переезжают в `design/tokens.json`; генератор выдаёт CSS, Swift и Kotlin, тест сверяет CSS с текущим (ПК-версия не меняется). Руками цвета не переносим. `DESIGN.md` не правим — источником остаётся он, `tokens.json` — его машинная копия.
- **Данные.** Своя `library.db` на телефоне, та же схема, миграции только вперёд. Файлы — в `Application Support`, папка исключена из резервной копии iCloud.

## 9. Сборка

Разработка — xtool в WSL; релизная IPA — macOS-раннер GitHub Actions. Оба пути — один SwiftPM-проект `apps/mobile-ios`.

Среда разработчика: (1) WSL2 + Ubuntu, Swift ≥ 6.3, `usbmuxd`, `libimobiledevice-utils`, актуальный xtool (1.24.0 на 2026-11-05); (2) на Windows `usbipd-win`: `usbipd bind` и `usbipd attach --wsl` пробрасывают iPhone в WSL; (3) `Xcode.xip` с developer.apple.com бесплатным Apple ID и `xtool setup`; (4) `rustup target add aarch64-apple-ios`, clang и SDK из xtool для C-зависимостей; (5) `scripts/build-ios-core.sh` — staticlib, xcframework и Swift-обёртки UniFFI; (6) `xtool dev` — собрать, поставить, запустить по кабелю.

Учитываем заранее: на Linux не собираются каталоги ресурсов, storyboard и Metal-шейдеры; иконка — PNG в `iconPath`, экран запуска — через Info.plist; SwiftData с `@Model` не работает (данные и так в Rust); виджет — расширение (продукт в `Package.swift` + запись в `xtool.yml`); метаданные App Intents формирует инструмент только для Mac на Apple Silicon — кнопки виджета и Siri проверяем на сборке из GitHub Actions; визуализация волны 3 — WebGL в WKWebView или Metal только в релизной сборке (решаем перед волной 3).

Релиз iPhone: workflow на macOS-раннере по тегу `mobile-v*` (публичный репозиторий — бесплатно, без лимита минут) → `xtool dev generate-xcode-project` → `xcodebuild CODE_SIGNING_ALLOWED=NO` → `sirtone-ios-<версия>-unsigned.ipa` → GitHub Releases с манифестом, sha256 и подписью канала обновлений. Если репозиторий станет закрытым (OWN-01), бесплатные 2000 минут с множителем 10 дают ~200 минут macOS в месяц.

## 10. Обновление и продление подписи (FR-HUB-RENEW)

Два пути: волна 1 — хаб, волна 2 — сам iPhone. Человек видит только «Работает ещё N дней».

**Через хаб (волна 1).** Продление — только новые профили приложения и виджета через `misagent`, без переустановки (так делает AltStore; подтверждает П3). Обновление версии — полная установка, только когда музыка не играет. Окно — за 3 дня до конца подписи, попытка при каждом появлении телефона. Подсказка от телефона: открытое или играющее приложение сообщает хабу «я здесь, осталось N дней» (решает проблему спящего iPhone). Планировщик живёт в трее ПК. Не получилось — за 2 дня баннер в приложении и локальное уведомление (единственное системное уведомление, D-135). После истечения приложение не откроется, но музыка и данные сохранятся.

| Сеть | Как идёт связь | Статус |
|---|---|---|
| Одна Wi-Fi-сеть | Wi-Fi-синхронизация через службу Apple | Известный рабочий путь |
| ПК на точке доступа iPhone | Та же служба | AltStore советует как обход |
| iPhone на точке доступа ПК | Та же служба | Отзывы пользователей, проверяем (П4) |
| Рабочий или гостевой Wi-Fi | Часто блокирует обнаружение | Подсказка про точку доступа или кабель |
| Кабель | `usbmuxd` | Всегда работает |

**Сам iPhone (волна 2, П9).** При установке хаб кладёт в приложение файл сопряжения RPPairing и токен сервисов разработчика (не пароль) — так устроено в SideInstaller (лицензия NC: берём идею, не код). Человек один раз ставит LocalDevVPN из App Store (мастер показывает картинками). Когда пора: «Включите LocalDevVPN, чтобы продлить работу» — продление по Wi-Fi в пару нажатий. Если хаб рядом — продлевает он, VPN не нужен. На iOS 26.4+ файл должен быть именно RPPairing (старые lockdown-файлы через VPN не работают); на iOS 27 есть сопряжение на самом телефоне.

## 11. Перенос между ПК и телефоном (FR-XFER-*)

Разовое действие по кнопке, в любую сторону; между переносами медиатеки живут отдельно и каждая учится своей волне.

| Направление | Что можно взять |
|---|---|
| ПК → телефон | Музыка и обложки, плейлисты, признаки анализа, отметки, журнал прослушиваний, модели волны, настройки и тема |
| Телефон → ПК | Добавленная на телефоне музыка, плейлисты, отметки, журнал прослушиваний |

- **Выбор:** всё сразу или галочками («Музыка», «Плейлисты», «Вкусы и волна», «Настройки и тема»); объём заранее.
- **Пакет:** `sirtone-transfer` собирает папку с манифестом, файлами и журналом событий; формат один для обеих платформ.
- **Кабель на iPhone:** `house_arrest` и `afc` кладут пакет в `Documents`; приложение запускать не нужно, разбор при открытии.
- **Докачка:** после обрыва — по манифесту.
- **Музыка:** дубли по отпечатку звука, статистика объединяется; аудио не перекодируем; файловые операции на ПК — через `fs_journal`.
- **Вкусы:** события с UUID не дублируются; у ♡ побеждает последняя отметка; модель волны пересчитывается из общего журнала, веса не складываются.
- **Без интернета:** перенос полностью локальный. **По Wi-Fi** (волна 2): тот же пакет через локальную сеть и сопряжение по QR.
- **Смена Apple ID** даёт новое приложение и новую папку данных: хаб перед сменой предлагает «Забрать с телефона», после установки возвращает данные.

## 12. Безопасность (FR-HUB-SEC)

- Пароль Apple ID не сохраняем. Токены и ключи — в Windows Credential Manager, отдельно для каждого аккаунта.
- Пароль, токены и код 2FA никогда не попадают в логи (у Impactor такая утечка кода 2FA уже была) — тест на отсутствие в логах обязателен.
- «Отключить телефон» удаляет токены, ключи и файлы сопряжения этого телефона. Для чужого телефона — «Не запоминать на этом ПК» после перехода на самопродление.
- Установочный файл ставим только после проверки sha256 и подписи канала обновлений.
- Пакет переноса создаётся только на доверенном кабельном или сопряжённом подключении.
- **Лицензии** (`08` §3, проверено `gh api` 2026-11-05): idevice, isideload, iloader, Impactor, xtool, adb_client — MIT; AltStore и SideStore — AGPL-3.0 (только идеи); Sideloadly — закрыт; SideInstaller — своя лицензия с запретом коммерческого использования (только идеи); libwdi — LGPL-3.0 (Zadig — GPL-3.0), `wdi-rs` — MIT/Apache, но тянет libwdi (Q-27); xlinux — GPL-3.0 (только как внешний инструмент сборки, не в бинарнике).
- **Условия Apple:** бесплатный аккаунт не предназначен для распространения приложений, вход по паролю в xtool/isideload идёт через приватные API. Схема рассчитана на себя и близких: каждый ставит своим Apple ID. Публичная раздача — отдельное решение владельца.

## 13. Риски и запасные пути

Главный риск — Apple регулярно меняет вход и связь с устройством: модуль установки придётся поддерживать, а не написать один раз.

| Риск | Что известно | Что делаем |
|---|---|---|
| Ломается вход в Apple ID | Impactor чинил вход в сентябре и дважды в октябре 2026 | Автообновление ПК-версии, запасной `plumesign`, понятный повторный вход |
| Обновление iOS ломает сопряжение | iOS 27 изменила файлы lockdown, iOS 26.4 перестала принимать их через VPN | Храним оба типа файлов, тест на бетах, повторное сопряжение кабелем |
| Anisette-сервер | Для входа нужен сторонний сервер, у Impactor уже менялся провайдер | Несколько адресов с перебором, проверить локальный вариант (Q-26) |
| Телефон 7 дней не видел хаб | Подпись истекает, приложение не открывается, данные целы | Предупреждение заранее, самопродление в волне 2 |
| Виджет на бесплатном аккаунте | Отзывы об App Group расходятся | П5, запасной вид без обложки |
| Лимит App ID | Приложение и виджет занимают 2 из 10 за неделю | Повторные установки под новыми ID запрещены, понятное сообщение |
| Лимит приложений | iOS считает все приложения всех бесплатных Apple ID на устройстве | Сиртон занимает один слот, хаб показывает, что мешает |
| Смена Apple ID | Новый Bundle ID и новая папка данных | Перед сменой забираем данные переносом |
| Анализ греет телефон | Фоновые задачи система запускает сама, чаще ночью на зарядке | П6, пауза при нагреве |
| Незрелые библиотеки | idevice ломает API, у isideload не закончены entitlements | Точные версии, трейт `PhoneInstaller`, запасной путь |
| Сервисы Apple недоступны из России | В июле 2026 сбоили App Store и сайт Apple | Окно 3 дня и повторы, понятное сообщение |
| xtool не потянет проект | Нет каталогов ресурсов, Metal и метаданных App Intents | Сборка в GitHub Actions; запасной — xlinux; последний вариант — Tauri iOS (только macOS) |
| LocalDevVPN исчезнет | Самопродление зависит от приложения в App Store | Хаб остаётся основным путём |
| Android и проверка Google | Мировой запуск в 2027 | ADB через хаб, решение о регистрации до запуска |
| Потеря ключа Android | Без него обновления невозможны | Секрет GitHub и офлайн-копия у владельца |
