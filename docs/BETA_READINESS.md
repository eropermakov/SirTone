# Готовность к публичной бете

Сверено: 2026-11-24. Этот документ различает работающий код, автоматическую проверку и ручную приёмку; отсутствие записи не означает разрешение на выпуск.

## Итог

**NOT READY.** Публичная бета заблокирована до устранения уязвимых транзитивных ZIP-зависимостей, macOS/iPhone-проверки и развёртывания production Feedback API. Выпуск, тег и push в рамках этой проверки не выполнялись.

## Подтверждено

- Фактическая линия: `stage/8-mobile`, исходный коммит аудита `948c436`; до работ она совпадала с `origin/stage/8-mobile`.
- На Windows уже были локальные rolling-журналы, panic-report и очистка старых журналов. D-180 теперь даёт стабильный Installation ID, Session ID на запуск, консервативный маркер незакрытой сессии, JSONL allow-list с лимитами, экспорт ограниченного ZIP, форму с локальным черновиком и добровольной HTTPS-отправкой.
- Подсказки первого запуска теперь явно объясняют добавление музыки, запуск воспроизведения, «Мой поток», настройки звука и путь к добровольному сообщению о проблеме; их обязательные пункты покрыты E2E.
- Есть локально тестируемый `services/feedback-api`: валидация ZIP без распаковки с проверкой central directory и local headers, rate limit с безопасной opt-in обработкой loopback proxy, HTTP/SMTP дедлайны, persistent idempotency с fail-closed поведением при повреждённом audit store, SMTP simulator и optional authenticated TLS SMTP. Пятнадцать API-тестов проходят. Windows при недоступном API сохраняет черновик и готовит `mailto:` без ложного обещания приложить ZIP; iOS-код использует тот же JSONL/ZIP формат, форму, Share Sheet и `MFMailComposeViewController`, собран в unsigned iPhoneOS bundle и установлен на подключённый iPhone. Запуск интерфейса и функциональная приёмка на устройстве ещё не подтверждены.
- `pnpm typecheck`, `pnpm lint`, `pnpm test`, `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, тесты diagnostics и проверка IPC bindings прошли на рабочем ПК. Для вновь подключённых runtime-сбоев отдельный privacy-тест доказывает, что путь и bearer-токен из `AppError.details` не попадают в JSONL.
- Диагностический Build ID Windows теперь содержит версию, канал и короткий commit; release-скрипт передаёт `stable` только в подписанную релизную сборку. iOS использует те же конфигурационные поля и получает фактический Build ID от release-процесса.
- Перед передачей локального или скачанного `.ipa` в `isideload` хаб теперь проверяет ZIP fixed-версией 9.0.5: совпадение local/central headers, безопасный путь, отсутствие symlink, единственный `Payload/*.app` и `Info.plist`. Тест подменённого local-header подтверждает отказ до Apple-сессии и распаковки. Это снижает эксплуатационный путь уязвимостей `isideload`, но не заменяет устранение самих транзитивных advisory.
- `release-ios.ps1` теперь передаёт в существующую WSL-сборку ID `<версия>-beta-<короткий-коммит>` и канал `beta`; `ios-sdk-stamp.py` записывает их в готовый Info.plist до подписи. На 2026-11-24 реально собраны XCFramework/UniFFI и unsigned arm64 iPhoneOS SwiftUI bundle через xtool 1.24.0 + Swift 6.4.2 + iPhoneOS SDK 27.1; проверенный Info.plist содержит `0.2.7`, `beta` и ожидаемый Build ID. Этот bundle впоследствии установлен на подключённый iPhone; это не подтверждает запуск или работу UI.
- Подключённый iPhone был обнаружен штатным `sirtone-cli phone list` по USB в состоянии `Ready`. На 2026-11-24 актуальный unsigned beta-bundle был реально установлен поверх SirTone через isolated hub smoke: сохранённая Apple-сессия использована без показа пароля, прогресс был виден, результат `installed on the iPhone` — 15,1 s. Этот smoke не читал медиатеку и не переносил музыку. Запуск приложения, подтверждение Developer Mode и остальная ручная приёмка iOS по-прежнему требуют владельца.
- `cargo nextest run --workspace --no-tests=warn` прошёл: 419 tests passed, 8 skipped. `sirtone-cli diagnostics inspect <report.zip> [--json]` читает только ожидаемые stored-файлы отчёта без распаковки на диск. Debug NSIS bundle собран локально: `SirTone_0.2.7_x64-setup.exe`, SHA-256 `5EA53698106CAE3BE39D3E4E132A1CB48F45B023051520FF22F1FB4FFF42049F`; он ожидаемо **NotSigned** и не устанавливался. После отключения неиспользуемого ZIP-extractor также прошла актуальная debug-сборка без bundling.
- Актуальная `pnpm tauri build --no-bundle` собрала production `target/release/sirtone-app.exe` (95 092 224 bytes); строка Build ID внутри артефакта совпадает с версией, каналом `development` и текущим коротким коммитом. Изолированный hub-smoke запускал эту сборку для установки iPhone-бандла; она не устанавливалась как Windows-инсталлятор.
- Полный браузерный Playwright smoke прошёл: 52 из 52. Во время production-сборки Vite всё ещё предупреждает о JavaScript-чанках больше 500 kB; это не блокирует тест, но требует отдельного performance-аудита до 1.0.
- `cargo deny check licenses bans sources` проходит (есть предупреждения о дублирующихся версиях в iPhone-цепочке). Проверка advisories намеренно не подавлена: она документированно блокирует бета-выпуск ниже.
- Регенерация `THIRD_PARTY_NOTICES.txt` и `assets/legal/notices.json` согласована с lockfile; проверка генератора и `git diff --check` проходят. Wave benchmark укладывается в бюджет: p95 5,40 ms при лимите 15 ms на 50 000 треков.
- CI без секретов добавлен в `.github/workflows/ci.yml`: он запускает quality gates только на pull request и вручную, не расходуя Windows minutes на каждый push. Отдельный `.github/workflows/ios.yml` готовит Rust XCFramework/Swift bindings и собирает iOS Simulator на затронутых PR либо вручную — без Apple ID, подписи, IPA или публикации. Release workflow остаётся выключенным до действия владельца, но закрепляет Rust 1.99, запускает полный набор quality gates перед релизом и работает с detached checkout GitHub Actions. Старый pending workflow больше не срабатывает автоматически по тегу.

## Блокеры

1. `cargo deny check` не проходит: RUSTSEC-2026-0545 и RUSTSEC-2026-0548 (а для одной ветки также 0546/0547) затрагивают `zip` 2.6.1 и 8.6.0 через `isideload`/`apple-codesign-quick`. Неиспользуемый ZIP-extractor Windows updater уже отключён: канал публикует прямой подписанный NSIS `.exe`. Нужен совместимый upgrade либо безопасное upstream-исправление цепочки iPhone-переноса с проверкой на устройстве. Отдельно RUSTSEC-2026-0543 отмечает неподдерживаемый `chrono` в той же транзитивной цепочке; безопасной замены в текущем upstream нет.
2. Production Feedback API не развёрнут: нет домена/HTTPS endpoint, настроенного persistent audit path/salt и SMTP credential в secret manager. Локальный тест не доказывает доставку в Gmail.
3. Физическая установка iPhone подтверждена, но нельзя подтвердить запуск и функции iOS на устройстве, установщик/обновление Windows в изолированной среде и 24-часовое Windows-воспроизведение из этой среды.
4. Нужны выпускной прогон в изолированной среде и ручная приёмка. Автоматический браузерный набор проходит; снимки обновлены после проверки: старые эталоны 0.2.2 не включали локальные пространства D-178.
