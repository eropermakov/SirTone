# Готовность к публичной бете

Сверено: 2026-11-25. Этот документ различает работающий код, автоматическую проверку и ручную приёмку; отсутствие записи не означает разрешение на выпуск.

## Итог

**NOT READY.** Публичная бета заблокирована до решения единственного оставшегося Rust advisory (`chrono` в iPhone signing-цепочке), ручной iPhone-проверки и развёртывания production Feedback API. Выпуск, тег и push в рамках этой проверки не выполнялись.

## Подтверждено

- Фактическая линия: `stage/8-mobile`, исходный коммит аудита `948c436`; до работ она совпадала с `origin/stage/8-mobile`.
- На Windows уже были локальные rolling-журналы, panic-report и очистка старых журналов. D-180 теперь даёт стабильный Installation ID, Session ID на запуск, консервативный маркер незакрытой сессии, JSONL allow-list с лимитами, экспорт ограниченного ZIP, форму с локальным черновиком и добровольной HTTPS-отправкой.
- Подсказки первого запуска теперь явно объясняют добавление музыки, запуск воспроизведения, «Мой поток», настройки звука и путь к добровольному сообщению о проблеме; их обязательные пункты покрыты E2E.
- Есть локально тестируемый `services/feedback-api`: валидация ZIP без распаковки с проверкой central directory и local headers, rate limit с безопасной opt-in обработкой loopback proxy, HTTP/SMTP дедлайны, persistent idempotency с fail-closed поведением при повреждённом audit store, SMTP simulator и optional authenticated TLS SMTP. Пятнадцать API-тестов проходят. Windows при недоступном API сохраняет черновик и готовит `mailto:` без ложного обещания приложить ZIP; iOS-код использует тот же JSONL/ZIP формат, форму, Share Sheet и `MFMailComposeViewController`, собран в unsigned iPhoneOS bundle и установлен на подключённый iPhone. Запуск интерфейса и функциональная приёмка на устройстве ещё не подтверждены.
- `pnpm typecheck`, `pnpm lint`, `pnpm test`, `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, тесты diagnostics и проверка IPC bindings прошли на рабочем ПК. Для вновь подключённых runtime-сбоев отдельный privacy-тест доказывает, что путь и bearer-токен из `AppError.details` не попадают в JSONL.
- Диагностический Build ID Windows теперь содержит версию, канал и короткий commit; release-скрипт передаёт `stable` только в подписанную релизную сборку. iOS использует те же конфигурационные поля и получает фактический Build ID от release-процесса.
- Перед передачей локального или скачанного `.ipa` в `isideload` хаб теперь проверяет ZIP fixed-версией 9.0.5: совпадение local/central headers, безопасный путь, отсутствие symlink, единственный `Payload/*.app` и `Info.plist`. Регрессионные тесты подменённого local-header и Unix symlink подтверждают отказ до Apple-сессии и распаковки. Два source-only maintenance fork (`isideload` 0.5.2 и `apple-codesign` 0.29.0) закрепляют тот же исправленный ZIP и сохраняют лицензии/происхождение в `third_party/`; ZIP advisory 0545/0546/0547/0548 больше не находятся `cargo deny`.
- `release-ios.ps1` теперь передаёт в существующую WSL-сборку ID `<версия>-beta-<короткий-коммит>` и канал `beta`; `ios-sdk-stamp.py` записывает их в готовый Info.plist до подписи. На 2026-11-24 реально собраны XCFramework/UniFFI и unsigned arm64 iPhoneOS SwiftUI bundle через xtool 1.24.0 + Swift 6.4.2 + iPhoneOS SDK 27.1; проверенный Info.plist содержит `0.2.7`, `beta` и ожидаемый Build ID. Этот bundle впоследствии установлен на подключённый iPhone; это не подтверждает запуск или работу UI.
- Подключённый iPhone был обнаружен штатным `sirtone-cli phone list` по USB в состоянии `Ready`. На 2026-11-24 актуальный unsigned beta-bundle был реально установлен поверх SirTone через isolated hub smoke: сохранённая Apple-сессия использована без показа пароля, прогресс был виден, результат `installed on the iPhone` — 15,1 s. Этот smoke не читал медиатеку и не переносил музыку. Запуск приложения, подтверждение Developer Mode и остальная ручная приёмка iOS по-прежнему требуют владельца.
- `cargo nextest run --workspace --no-tests=warn` прошёл: 419 tests passed, 8 skipped. `sirtone-cli diagnostics inspect <report.zip> [--json]` читает только ожидаемые stored-файлы отчёта без распаковки на диск. Актуальный release NSIS-кандидат собран локально: `SirTone_0.2.7_x64-setup.exe` (37 476 727 bytes), SHA-256 `F753BE90A0FBA9038B6EA48A83382FFDB1F7C9947D971CC52B06FFED2F6022A1`; он ожидаемо **NotSigned** и не устанавливался. Production source maps выключены и отсутствуют из `dist`; установка на основной учётной записи не является изолированной, потому что hooks намеренно регистрируют `Open With` в HKCU, поэтому для install/update/uninstall-smoke нужна VM либо чистая Windows-учётная запись. После отключения неиспользуемого ZIP-extractor также прошла актуальная debug-сборка без bundling.
- Актуальная `pnpm tauri build` собрала production `target/release/sirtone-app.exe` (93 916 160 bytes); Build ID в бинарнике — `0.2.7-development-61d7f1b781e4`, то есть версия, development-канал и точный короткий commit исходников candidate. Изолированный hub-smoke запускал эту сборку для установки iPhone-бандла; она не устанавливалась как Windows-инсталлятор.
- Актуальный release `real-app` smoke на `target/release/sirtone-app.exe` прошёл 121 из 121 проверок в отдельной временной папке: запуск и ввод, импорт корпуса из 500 файлов, воспроизведение и обработка битого файла, очередь, SQLite-журнал и миграционные сценарии, watcher, перенос файлов, поиск, «Мой поток», анализ, визуализации, доступность, Windows SMTC и запуск в minimised-режиме. Для запуска smoke были сгенерированы игнорируемые детерминированные fixtures; пользовательские данные не использовались.
- Полный браузерный Playwright smoke прошёл: 52 из 52. Во время production-сборки Vite всё ещё предупреждает о JavaScript-чанках больше 500 kB; это не блокирует тест, но требует отдельного performance-аудита до 1.0.
- Физическая проверка подключённого iPhone обнаружила регрессию в предрейлизном Windows-хабе: AFC корректно сообщает 22 338 MB свободного места, но preflight ошибочно требовал почти двойной размер входящего пакета. Коммит `46d8afa` учитывает фактически недостающую часть пакета и 256 MB reserve: импорт на iOS перемещает файл в библиотеку внутри одного container, не создавая вторую полную копию. Подготовка manifest и экономная перекодировка теперь публикуют ограниченный прогресс вместо неподвижных 2 %. `cargo test -p sirtone-sync -p sirtone-devicelink -p sirtone-app` прошёл: 73 tests; это не заменяет повторную пользовательскую передачу музыки после установки нового Windows-кандидата.
- На 2026-11-25 полноценный `pnpm tauri build --bundles nsis` собрал новый Windows installer после исправления передачи: `SirTone_0.2.7_x64-setup.exe` (37 562 018 bytes), SHA-256 `95C35209972430D4C090A82B95495C0C5C8CC0A99E7DB4D5EEE5329926B72020`. NSIS bundle собран, но он **NotSigned**: Tauri не создал updater signature без `TAURI_SIGNING_PRIVATE_KEY`. Технический `cargo build` executable не является распространяемым артефактом: он не упаковывает frontend и может открыть `devUrl` (`localhost`); для проверки используется только Tauri bundle/installer.
- `cargo deny check licenses bans sources` проходит (есть предупреждения о дублирующихся версиях в iPhone-цепочке). Проверка advisories намеренно не подавлена: после устранения ZIP цепочки она блокирует выпуск только по отдельному upstream advisory `chrono` ниже.
- `pnpm audit --prod` не находит известных уязвимостей production Node-зависимостей; этот результат не отменяет отдельный блокер Rust/iPhone advisory.
- Регенерация `THIRD_PARTY_NOTICES.txt` и `assets/legal/notices.json` согласована с lockfile; проверка генератора и `git diff --check` проходят. Wave benchmark укладывается в бюджет: p95 5,40 ms при лимите 15 ms на 50 000 треков.
- CI без секретов добавлен в `.github/workflows/ci.yml`: он запускает quality gates только на pull request и вручную, не расходуя Windows minutes на каждый push. Отдельный `.github/workflows/ios.yml` готовит Rust XCFramework/Swift bindings и собирает iOS Simulator на затронутых PR либо вручную — без Apple ID, подписи, IPA или публикации. Release workflow остаётся выключенным до действия владельца, но закрепляет Rust 1.99, запускает полный набор quality gates перед релизом и работает с detached checkout GitHub Actions. Старый pending workflow больше не срабатывает автоматически по тегу.

## Блокеры

1. `cargo deny check advisories` не проходит только по RUSTSEC-2026-0543: неподдерживаемый `chrono` в транзитивной iPhone signing-цепочке (`isideload`/`apple-codesign`/`idevice`). У advisory нет безопасной версии обновления; это не подавлено. Закреплённые source-only forks в `third_party/` уже устранили ZIP 2.6.1/8.6.0 и RUSTSEC-2026-0545/0546/0547/0548, но не заменяют `chrono`.
2. Production Feedback API не развёрнут: нет домена/HTTPS endpoint, настроенного persistent audit path/salt и SMTP credential в secret manager. Локальный тест не доказывает доставку в Gmail.
3. Физическая установка iPhone подтверждена, но нельзя подтвердить запуск и функции iOS на устройстве, установщик/обновление Windows в изолированной среде и 24-часовое Windows-воспроизведение из этой среды.
4. Нужны выпускной прогон в изолированной среде и ручная приёмка. Автоматический браузерный набор проходит; снимки обновлены после проверки: старые эталоны 0.2.2 не включали локальные пространства D-178.
