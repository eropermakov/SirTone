## A. Автомикс, кроссфейд и переходы между треками

**Референсы (11):** Apple Music AutoMix · Spotify (Crossfade / Automix / Mix) · Plexamp Sweet Fades · Mixxx Auto DJ · djay Automix · VirtualDJ AutoMix · MPD MixRamp · foobar2000 (fading + Sqrsoft Advanced Crossfader) · RadioBOSS · Rockbox · JRiver Media Center.

### A.1. Как это работает у них

| Приложение | Что делает / как устроено | Ур. | Ист. |
|---|---|---|---|
| **Apple Music AutoMix** (iOS 26 / macOS Tahoe) | ИИ анализирует аудиопризнаки и строит переход; использует **time stretching и beat matching**; сам выбирает тип: например, **убирает тишину в начале/конце** или делает **простой кроссфейд** вместо сложного перехода, «когда это уместно». **Альбомы и часть жанров играют без переходов.** Включено по умолчанию. Настройка «Song Transitions»: AutoMix / Crossfade / Off. Ключ (тональность) в официальных описаниях не подтверждён. Кроссфейд: ползунок **1–12 с**; в Android-версии режим «Automatic» подбирает длину по песне. Недоступно при AirPlay. | ○ | S7, S15 |
| **Spotify** | Три независимых тумблера: **Crossfade** (ползунок в Playback; Premium), **Automix** («beat-matched seamless transitions» на «select playlists», **работает и при shuffle**), **Gapless**. Нельзя менять при Spotify Connect. **Mix** (август 2025, плейлисты): пресеты **Fade / Rise / Blend**, ручные громкость/EQ/эффекты по трекам, **данные о форме волны и битах** помогают выбрать точку перехода, **показывает BPM и тональность** каждого трека; «Smart Reorder» (2026) переставляет по BPM/тональности. Лучше всего на электронике. | ✔/○ | S5, S6 |
| **Plexamp — Sweet Fades** | Не фиксированные «N секунд до конца»: анализирует **конец текущего и начало следующего** трека и для каждой пары считает свой момент и длину перекрытия. Использует **анализ громкости (выборки ≈10 раз в секунду)** — «звуковой отпечаток громкости»; без него не работает. **Автоматически отключается при воспроизведении альбома** (определяет «очередь = полный альбом по порядку») и заменяется на gapless. | ○ | S8 |
| **Mixxx — Auto DJ** | Управляет кроссфейдером двух дек. Режимы: **Full Intro + Outro (по умолчанию)** — играет полностью интро и аутро, перекрывая их; **Fade At Outro Start**; **Full Track** (кроссфейд N секунд); **Skip Silence** (режет тишину ниже **−60 dBFS** в начале/конце); Skip Silence Start Full Volume. Длина перехода = **меньшее из «аутро уходящего» и «интро входящего»**. Маркеры интро/аутро ставит анализатор (начало интро = первый звук, конец аутро = последний звук), пользователь правит. Не учитывает громкость, частоты, ритм. Ноль секунд = обычный плеер. Случайное пополнение очереди из «крейтов», перезапуск сыгранных в конец. | ✔ | S1 |
| **djay — Automix** | Источники очереди: Manual / **Matching Songs** (ИИ подбирает подходящие) / Current Playlist. **Transition**: Automatic (**случайный выбор стиля**) / Fade / Filter / EQ / Echo / Dissolve / Neural Mix (разделение на стемы) / Riser / Tremolo. **Duration**: Automatic или вручную в **тактах или секундах**. **Tempo adjust**: Off / **Sync** (держит один BPM) / **Sync + Tempo blend** (плавно подтягивает темп уходящего к входящему) / **Automatic** (выравнивает BPM, если разница заметна; если близки — держит текущий). **Song range**: start/end point (Auto или вручную X с), «использовать маркеры трека», «Maximum song play duration». **Mix Now** — начать переход «в ближайшей подходящей точке». Skip — просто перейти. | ✔ | S3, S4 |
| **VirtualDJ — AutoMix** | Типы миксов: **fade, cut, tempo** — выбирается **наивысший тип, приемлемый обоим трекам**; «force fade». При анализе BPM-движок вычисляет для каждого трека, какие миксы совместимы, и **точки входа/выхода для каждого типа**; точки правятся пользователем (POI-редактор). Tempo-микс разрешён, если BPM укладываются в диапазон питча (в опциях **±8 / ±12 / ±34 %**). Длина фейда **0–16 с**; можно задавать в битах вместо секунд. Типичная проблема — ошибки BPM «×2 / ÷2» (в редакторе есть кнопки /2 и ×2). | ○ | S13 |
| **MPD — MixRamp** | Альтернатива кроссфейду: **перекрытие по порогу громкости** без затухания. `mixrampdb` — порог (в docs советуют **−17 dB**), `mixrampdelay` — вычитается из перекрытия; теги `MIXRAMP_START/END` (считает внешний инструмент, рекомендация автора: −6 dB и 0,5 с) или встроенный `mixramp_analyzer` (0.24+). Условия: включён crossfade, одинаковый аудиоформат. **Fallback — обычный кроссфейд, если тегов нет.** | ✔ | S9 |
| **foobar2000** | Встроенные **fade**-времена на пауза/стоп, ручную смену трека и автопереход (по умолчанию ≈100 мс везде, кроме автоперехода); встроенный кроссфейд с v1.1.11, **в том числе при ручной смене**. Sqrsoft Advanced Crossfader (DSP): **начало/конец микса по уровню в dB**, своё время fade, начальный уровень и кривая. | ○ | S10 |
| **RadioBOSS** (вещательный) | Параметры: **Trigger mix at** — порог уровня (**по умолчанию −14 dB**, смотрит пик, а не среднее), **Mix point** — минимальное перекрытие (**по умолчанию 2,5 с**), fade-in/out, «Start fading out on mix», «Override previous track mix». | ✔ | S11 |
| **Rockbox** | Режим: Off / Только автоматическая смена / Только ручная / При shuffle / Всегда. Параметры: **Fade In Delay, Fade In Duration, Fade Out Delay, Fade Out Duration**, **Fade Out Mode: Crossfade или Mix** (Mix — уходящий не затухает, входящий нарастает под ним; для ручных пропусков не используется). Защита: если «задержка+длительность затухания» меньше «задержки появления» — задержка появления сокращается, чтобы не было провала. | ✔ | S12 |
| **JRiver MC** | Два режима: по умолчанию — кроссфейд с **удалением тишины** на стыках; «Gapless» — как есть. Длина кроссфейда по умолчанию ≈ 4 с; настройки зависят от режима. | ○ | S14 |

### A.2. Что общего у всех (ядро механики — копируем)

1. **Трёхуровневая лестница.** Везде: *без переходов (gapless)* → *простой кроссфейд фиксированной длины* → *«умный» переход по анализу* (Apple: AutoMix/Crossfade/Off; Spotify: Gapless/Crossfade/Automix/Mix; Rockbox, JRiver, Mixxx — аналогично).
2. **Альбомы не микшируются** (Apple — альбомы и часть жанров; Plexamp — «очередь = альбом» → gapless; Spotify Automix — только «select playlists»).
3. **Тип перехода выбирает анализ, с понижением до простого при недостатке данных**: Apple (тишина/кроссфейд вместо сложного), VirtualDJ (наивысший общий тип: tempo → fade → cut), MPD (нет тегов → кроссфейд), Mixxx (интро+аутро → skip silence).
4. **Момент перекрытия определяется по уровню/огибающей громкости, а не «за N секунд до конца»**: Plexamp (10 выборок/с), MPD (порог dB), RadioBOSS (−14 dB), Sqrsoft (dB), Mixxx (−60 dBFS тишина).
5. **Beat-matching только при сопоставимом темпе** и с ограничением на растяжение: VirtualDJ ±8/12/34 %, djay «Automatic» (подтягивает только если разница заметна), Spotify/Apple (time-stretch).
6. **Стили перехода**: Fade, Filter, EQ(-swap), Echo, Blend/Rise, Dissolve (djay, Spotify Mix). «Automatic» у djay — случайный; у Spotify Mix — автопредложение.
7. **Ручной пропуск ≠ авто-переход**: Rockbox (отдельный режим для ручных), foobar2000 (fade на ручную смену), djay (Skip vs **Mix Now**).
8. **Длина**: пользовательский ползунок **1–12 с** (Apple ✔, Spotify), 0–16 с (VirtualDJ), по умолчанию 2,5 с мин. перекрытие (RadioBOSS), ≈4 с (JRiver).
9. **Пользователь может править точки** трека (Mixxx, VirtualDJ POI, djay «song range») — как минимум «использовать маркеры, если есть».
10. **Анализ BPM/тональности не безупречен**: Mixxx (constant-tempo assumption, быстрый анализ по первой минуте), VirtualDJ (/2 и ×2), стратегии отката обязательны.
11. **Time-stretch**: DJ-приложения используют Rubber Band (Mixxx, **GPL**) / élastique (проприетарный) / SoundTouch (**LGPL**) ◌ — для нас по лицензиям подходит **Signalsmith Stretch (MIT)**.

### A.3. Решение для SirTone (копия + адаптация)

| Элемент | Решение | Копия у кого |
|---|---|---|
| Режим переходов | `Без переходов (gapless)` · `Кроссфейд` · `Умный автомикс` (+ вкл/выкл и интенсивность — требование ✅ владельца) | Apple / Spotify / Rockbox |
| Исключения | Не микшируем, если очередь = альбом в исходном порядке (определение по `album_id` + возрастанию `track_no`), а также для жанров из чёрного списка (классика, live, ambient, аудиокниги) | Apple, Plexamp |
| Выбор перехода | Лестница отката: **L3 beatmatch** (оба трека: BPM-уверенность ≥ 0,8, разница темпа в допуске, при необходимости ×2/÷2) → **L2 перекрытие по огибающей** (как Plexamp/MPD) → **L1 срезка тишины + gapless** (как Apple/Mixxx Skip Silence) → **L0 gapless** | VirtualDJ, Apple, MPD |
| Точка перекрытия | По огибающей громкости (10 Гц, считается при анализе): выход = последний момент, где краткосрочная громкость ≥ (громкость трека − 17 dB), вход = первый такой момент; потолок/пол длины 2…12 с; привязка к границе такта при L3 | MPD (−17 dB), Plexamp, RadioBOSS |
| Минимум перекрытия | 2,5 с (если порог сработал слишком поздно) | RadioBOSS |
| Длина перехода (ручной кроссфейд) | Ползунок **1–12 с**, по умолчанию 6 с | Apple, Spotify |
| Стили L3 | `Fade` (equal-power), `Blend` (EQ-swap: бас уходящего вырезается, бас входящего возвращается), `Filter` (sweep). Echo/Riser/Dissolve/Neural Mix — вне v1 | djay, Spotify Mix |
| «Automatic» | Выбор стиля **по правилам** (электроника/танцевальное → Blend; остальное → Fade), а не случайно | отличие от djay (там random) |
| Допуск темпа | Низкая интенсивность: растяжение 0 % (только L2); Средняя: ≤ 6 %; Высокая: ≤ 10 %; кроме того учитываем ×2/÷2 | VirtualDJ (±8/12), djay |
| Совместимость тональностей | Круг Камелот (Camelot): та же ячейка или ±1, A↔B; несовместимо → **не EQ-swap-ом дольше 4 с**, а короткий fade | Spotify Mix (показывает key), Mixxx key |
| Ручной «Следующий» | Короткий fade 300 мс; плюс команда «**Смешать сейчас**» (ближайшая подходящая точка) | foobar2000, djay (Mix Now) |
| Маркеры | Автоопределение; пользователь может задать «начало/конец» трека (C) | Mixxx, VirtualDJ, djay |
| Time-stretch | Signalsmith Stretch (MIT), блоковый режим с плавной сменой коэффициента | замена Rubber Band/élastique |
| Эксклюзивный/bit-perfect режим | Автомикс и кроссфейд недоступны (только gapless) — индикатор объясняет почему | Spotify/Apple: «недоступно при Connect/AirPlay» |
| Тест | Объективный: ошибка фазы битов ≤ 20 мс на тест-клике; отсутствие щелчков; уровень на стыке ±1 dB; субъективный A/B на 30 парах | — |

**Что осознанно НЕ копируем:** случайный выбор стиля (djay Automatic), Neural Mix/стемы, голосовой DJ, облачный подбор «подходящих песен», платные ограничения.

## B. Визуализация

**Референсы (12):** Winamp MilkDrop · projectM · Butterchurn (Webamp, Music Assistant) · Kodi (visualization add-ons) · VLC (projectM/Goom/glspectrum) · Windows Media Player · iTunes Visualizer · Poweramp · Spotify Canvas · Apple Music (анимированный фон) · «Моя волна» Яндекс Музыки · Wallpaper Engine / Lively / Rainmeter.

### B.1. Какие данные хост передаёт визуализатору

| Приложение | Формат и размер аудиоданных | Синхронизация / частота | Ист. |
|---|---|---|---|
| Winamp vis API | `waveformData[2][576]` и `spectrumData[2][576]`, **8 бит unsigned**, до 2 каналов | `delayMs` — интервал вызовов Render (по сути, потолок FPS; MilkDrop2: «10 ≈ 100 FPS»), `latencyMs` — задержка | ○ S24 |
| iTunes Visual SDK | `waveformData[2][512]`, `spectrumData[2][512]`, 8 бит; **timestamp** в сообщении Render; плагин при регистрации заявляет, сколько каналов и как часто хочет | render-сообщения с временной меткой | ○ S26 |
| Windows Media Player (IWMPEffects) | `TimedLevel`: `frequency[2][1024]`, `waveform[2][1024]` (8 бит; waveform со смещением 128), `state`, **`timeStamp` (100 нс)**; частоты от 20 Гц до 22 050 Гц | снимок «через определённые интервалы» | ✔ S25 |
| projectM | PCM **float −1…1**, моно/стерео (стерео interleaved LRLR), внутри приводится к 2-канальному float; `projectm_pcm_get_max_samples()` (**512 на канал**); FFT считает сам | вызывается хостом каждый кадр | ✔ S20 |
| Kodi (vis add-on) | `AudioData(const float*, size_t)` — только PCM; `AudioStart(channels, samplesPerSec, bitsPerSample)`; **`AudioGetSyncDelay()`** — «сколько буферов подождать до AudioData» (**компенсация задержки вывода**); `Render()`, `IsDirty()`; пресеты: Get/Next/Prev/Random/Load/**Lock/Rate** | рендер по вызову хоста | ✔ S23 |
| Butterchurn | Время-доменные массивы (**1024 отсчёта**, 8 бит) для mono/L/R (`timeByteArray*`), FFT считает сам; **`render({audioLevels:{timeByteArray, timeByteArrayL, timeByteArrayR}, elapsedTime})` — можно подавать данные без WebAudio** (метод `updateAudio`) | `elapsedTime` задаёт тайминг | ✔ S21 |
| VLC | Аудио-кадры из конвейера; glspectrum делает FFT с окном | — | ○ S27 |
| MilkDrop (ядро) | Переменные пресета: `bass/mid/treb` (≈1 — норма; <0,7 тихо; >1,3 громко), сглаженные `*_att`, `vol`; `time`, `frame`, `fps`, `progress` (позиция в пресете) | — | ✔ S22 |

**Вывод (копируем):** хост отдаёт **короткое окно времени-доменного сигнала 512–1024 отсчёта на канал (L/R), 8-бит или float, с временной меткой и поправкой на задержку вывода**; всё остальное (FFT, полосы, биты) — на стороне визуализатора. Это ровно то, что принимает Butterchurn.

### B.4. Решение для SirTone (копия + адаптация)

| Элемент | Решение | Копия у кого |
|---|---|---|
| Контракт «хост → визуализатор» | Кадр: `timestamp_ms` проигранного аудио, `beat_phase` (из сетки битов), `bands[3]`, **`i8[1024]` mono + L + R**; частота ≤ 60 Гц; **задержка вывода учтена на стороне Rust** (тап сдвигается на `output_latency`) | WMP/iTunes (timestamp), Kodi (`AudioGetSyncDelay`), Butterchurn (формат) |
| Интерфейс движка визуализации | `init / setAudioFrame / setVibe / setPalette / resize / setQuality / dispose`; режим переключается на лету | Winamp/Kodi/VLC (хост отдаёт данные отдельному рендереру) |
| Режим «Волны» (цветовые) | Шейдер: потоковые цветовые пятна; **такт — по сетке битов**; **высокие частоты → блики**; **лайк/клик → импульс**; движение курсора → **белые импульсы**; цвета = смесь «цвета пользователя» и палитры настроения; «минималистичный» вариант | Яндекс «Моя волна», Apple/AMLL (низкие частоты → фон) |
| Режим «MilkDrop» | Butterchurn 2.6.7 + curated-набор пресетов; `audioLevels` вместо WebAudio; **30 с на пресет, мягкий переход 3 с, hard-cut выключен**, `Lock` и `Like/Dislike` (Rate); при смене трека — новый пресет по «вайбу» | projectM defaults, Kodi, Poweramp |
| Режим «Видео» | Зацикленные ролики **3–15 с, без звука**, WebM VP9/AV1 (или H.264 как запасной), пользовательские добавляются в интерфейсе | Spotify Canvas |
| Качество по уровням | Mesh: 24×18 (L1) / 32×24 (L2) / 48×36 (L3–L4); `pixelRatio` ≤ 1 на L1–L2; `textureRatio` 0,5–1; FXAA только L4; **FPS-потолок 30 / 45 / 60** | projectM, Butterchurn, Wallpaper Engine |
| Пауза и экономия | Пауза при: окно свёрнуто/перекрыто (≥ 95 % — как Lively), полноэкранное приложение (`SHQueryUserNotificationState`), режим экономии заряда/батарея → автоматически ниже уровень | Wallpaper Engine, Lively, Chrome Energy Saver |
| Иммерсивный режим («ночной вайб») | Полный экран; интерфейс **плавно скрывается при бездействии**, возвращается по движению мыши/клавише; Esc — выход; `ES_DISPLAY_REQUIRED` пока играет | Poweramp (Fade/Hidden), Яндекс (скрытие UI), Webamp |
| Рамка кадра | Не обновлять CSS-переменные корня чаще 4 Гц — рисовать в canvas/WebGL | урок LUMEN (50-мс тик перерисовки корня съел память) |

**Что осознанно НЕ копируем:** собственную реализацию MilkDrop (используем Butterchurn), набор из тысяч пресетов (curated ~300–600 + индекс), видеоролики «из коробки» без проверки лицензий.


### B.5. Кинетическая типографика титров (референс владельца, 2026-10-27)

| Шрифт | Широкий вид стиля 1 и сверхузкий стиля 2 — горизонтальный масштаб единственного семейства ≈ 1,2–1,3 и 0,55–0,65 | Только Geologica (D-122): масштаб на canvas, отдельного дисплейного шрифта нет |

### C.2. Что общего (копируем)

1. **Движок отделён от UI**; UI не играет звук: Spotify (нативное ядро+CEF), Plexamp (MPD), Roon (Core/Remote/Output), Tauri-плееры (Rust-ядро). → *Rust-ядро + WebView-UI.* ✔
2. **Конвейер звука из стадий**: demux → decode → (resample) → фильтры/DSP → output (VLC, MPD, Winamp, GStreamer/Strawberry). Визуализация — **ответвление после DSP** (Winamp: vis получает данные из выходного потока). → наш `decode → resample → DSP/mix → limiter → ring → WASAPI` + тап для vis. ✔
3. **Ресемплер — сменный и качественный** (MPD: internal/libsamplerate/soxr; Strawberry/GStreamer). → `rubato`. ✔
4. **Выход — сменный плагин** (MPD `wasapi`, MusicBee WASAPI shared/exclusive/ASIO, VLC добавил exclusive). → трейт `AudioSink`, реализации shared/exclusive. ✔
5. **Gapless = предоткрытие следующего трека** (LUMEN, GStreamer «about-to-finish», MPD prefetch). ✔
6. **Библиотека на SQLite** (Strawberry, Navidrome, WaveFlow, LUMEN, **foobar2000 v2 ушёл от «базы в памяти» к SQLite** ради скорости старта и памяти). ✔ Подтверждает `rusqlite` + FTS5.
7. **События и колбэки вместо опроса** (foobar2000 `play_callback`, MusicBee notifications, Winamp messages). **Но синхронные обработчики — зло** (MusicBee: медленный плагин блокирует плеер) → у нас все события асинхронные и буферизуются.
8. **Сканер + watcher + «missing»-состояние** с сохранением статистики при переименовании (Navidrome ✔, Plex ✔, WMP monitored folders ✔).
9. **Конфигурация и портативность**: foobar2000 — маркер-файл `portable_mode_enabled`, всё в папке приложения, без реестра, **без ассоциаций файлов**; AIMP Portable — данные в `Data`, ловушки с ассоциациями и «неаккуратным» отключением флешки (файлы остаются в `%APPDATA%`). → маркер `sirtone.portable`, ничего вне папки. ✔

## D. Анализ темпа и тональности (B1, спайк S-08, T3.7)

**Референсы (6):** Mixxx · Traktor · djay Pro · VirtualDJ · Spotify (Audio Features / Mix) · Mixed In Key ◌ (как эталон точности в замерах `stratum-dsp`).

| Приложение | Как работает | Ур. | Ист. |
|---|---|---|---|
| **Mixxx** | Тональность — два анализатора на выбор: QM-DSP (по умолчанию, быстрый: частота дискретизации ÷8 и каждое 8-е окно, ×64 к скорости) и **KeyFinder** (с 2.3; точнее, но медленнее); «**Быстрый анализ**» — тональность по первой минуте; повторный анализ при смене анализатора; темп — сетка битов в предположении **постоянного темпа** | ✔ | S2, S136 |
| **Traktor** | Темп бывает найден **вдвое меньше или больше**; лечится **диапазоном BPM** в настройках анализа и кнопками **/2 и ×2** в панели сетки битов | ✔ | S137 |
| **djay Pro** | Тот же способ — **диапазон анализа** (например 58–115 против удвоения медленных, 98–195 для драм-н-бейса), анализ по папкам жанров | ○ | S138 |
| **VirtualDJ** | Ошибки «×2 / ÷2» — кнопки в редакторе; темп-микс только при BPM в диапазоне питча | ○ | S13 |
| **Spotify** | Audio Features: `tempo`, `key`, `mode` (+ уверенность в Audio Analysis); в Mix (2025) **показывает BPM и тональность** каждого трека | ○ | S5, S6 |
| **Mixed In Key** ◌ | Коммерческий эталон: в замере `stratum-dsp` — BPM ±2 у 98,1 %, тональность 72,1 % на 155 треках | ◌ | S139 |

**Что общего:** (1) ошибки ×2/÷2 неизбежны — их гасят **диапазоном темпа** и ручными /2, ×2; (2) тональность по хроме с шаблонами (Krumhansl–Kessler — `stratum-dsp`, KeyFinder) — около 70–80 % верных, поэтому **показывается/используется с уверенностью**; (3) быстрый режим — анализ части трека (Mixxx: первая минута); (4) в нотации DJ — **Camelot** (1A…12B).

**Решение для SirTone (копия + адаптация):** B1 = `stratum-dsp` 1.0 (MIT OR Apache-2.0; HMM-сетка битов, Krumhansl–Kessler; по README: BPM ±2 = 87,7 %, тональность 72 %, ≈12 % октавных ошибок, 150–350 мс на трек) — **если спайк S-08 подтвердит на нашем корпусе**; темп приводится к **диапазону 70–180 BPM** удвоением/делением (как Traktor/djay), в волну и автомикс идут только `bpm_conf ≥ 0,8` (иначе признак «не определён»); тональность — в Camelot (`key_camelot`) с уверенностью. Ручные /2 и ×2 — в карточке трека (позже). Источник истины по точности — золотой набор владельца (OWN-08).
