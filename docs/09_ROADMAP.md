# 09. Дорожная карта, задачи, спайки, критерии готовности

> Версия 1.5 · 2026-10-16 · этапы 1–6 — из ТЗ владельца (§24) + встраивание дополнения «Умная волна» (§36 дополнения) + мои этапы 0 (фундамент и спайки) и 7 (закалка). Размер задач: **S** ≤ полдня · **M** 1–2 дня · **L** 3–5 дней (ориентир для Claude Code). Приоритеты M/S/C — `02_TZ.md`.

---

## 1. Правила выполнения

1. **Спецификация — закон.** Любое отклонение — через ADR в `10_DECISIONS.md` (дата, контекст, решение, последствия). Нет ссылки на референс (`01_*`) — сначала поищи референс.
2. **Тонкие вертикальные срезы:** каждая задача завершается работающим, протестированным поведением (а не «заготовкой»).
3. **Тесты вместе с кодом;** бюджеты `08` §1 проверяются на этапе их появления.
4. **Коммиты — локально после каждой готовой задачи (D-36), push — только по команде владельца** (в Этапе 6 владелец даёт команду «релиз» — Claude Code собирает и публикует ✅). Ветка этапа `stage/N-<имя>`, слияние в `main` после приёмки этапа.
5. **Ничего тяжёлого без выключателя** (пресеты `06` §6). Ничего без i18n-ключа. Ничего без токена дизайна.
6. **Не ломать данные пользователя:** файловые операции — только через журнал; удаление — только в Корзину.
7. **Skills/MCP** (ТЗ §24): `context7` — документация Tauri/Rust/крейтов; `playwright` — реальная проверка UI; `figma` — перенос дизайна (после макетов владельца); `shadcn` — компоненты; скиллы дизайна — при реализации визуала владельца (`06` §1.2). `supabase` не нужен ✅.

### Definition of Done

| Уровень | Критерии |
|---|---|
| **Задача** | код + тесты зелёные; `clippy -D warnings`, `fmt`, `biome`; нет `unwrap()` вне тестов и инициализации; RT-путь без аллокаций; i18n-ключи; ADR при решении; документация обновлена |
| **Этап** | все M-требования этапа закрыты; приёмочные сценарии этапа проходят; бюджеты не хуже; `cargo deny` чист; журнал спайков и решений обновлён; демо-запись/скриншоты |
| **Релиз** | `08` §6 чек-лист; обновление «0.x → 0.y» проверено на чистой ВМ и на машине владельца; портативная запущена с флешки; `/security-review`; THIRD_PARTY_NOTICES |

## 5. Критерии отказа от Tauri (ТЗ: «✅ при условии, что весь функционал реализуем без компромиссов»)

Tauri 2 признаётся недостаточным, если **одновременно**: (a) S-03 не даёт одновременно внешний drop файлов и внутренний DnD; **или** (b) S-09 — ни одна стратегия слоя виджета не работает **и** нативная замена виджета невозможна в рамках Tauri; **или** (c) S-04 — кадры визуализации невозможно доставить стабильно ≥ 30 Гц без заметных рывков. Тогда предложить владельцу альтернативу (отдельное нативное окно виджетов; крайний случай — смена оболочки UI) с оценкой стоимости. До тех пор — продолжаем на Tauri 2. По текущим данным (подтверждены докой Tauri): конфликт HTML5-DnD ↔ нативный drop **известен и обходится pointer-DnD**; остальное проверяется спайками.
