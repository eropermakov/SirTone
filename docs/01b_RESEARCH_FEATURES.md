## F-01. Воспроизведение: форматы, декодеры, вывод, gapless

**Референсы (9):** foobar2000 · Winamp · MusicBee · AIMP · MPD · VLC · Strawberry (GStreamer) · Spotify · Roon.

| Приложение | Как работает | Ур. | Ист. |
|---|---|---|---|
| MPD | Декодеры — плагины (~24: flac, mad, mpg123, vorbis, opus, wavpack, sndfile, …); ресемплер сменный (internal / libsamplerate / **soxr**); вывод — плагины (в т.ч. **wasapi**) | ✔ | S43 |
| MusicBee | Движок BASS; вывод **WASAPI shared и exclusive + ASIO**; в exclusive поток идёт мимо микшера Windows, системные эффекты не действуют, другие приложения лишаются звука на устройстве | ○ | S45 |
| VLC | Конвейер access→demux→decoder→фильтры→**audio output**, вывод ресемплирует кадры под частоту устройства; опция **WASAPI exclusive** добавлена патчем 2019 г. | ○ | S42, S87 |
| Winamp | `in_*` декодеры → цепочка `dsp_*` → `out_*`; vis-плагины получают данные из выходного потока | ○ | S49 |
| Strawberry | GStreamer-конвейер; ReplayGain и EBU R128; эквалайзер | ✔ | S44 |
| Spotify | **Gapless** — отдельный тумблер (Premium) | ✔ | S5 |
| Roon | Устройство вывода **само тактирует** звук, ядро «пушит» буферизованный поток | ○ | S46 |
| AIMP | Декодер Opus — плагином; эквалайзер 18 полос | ○ | S86 |
| foobar2000 | Декодеры/DSP/выходы — компоненты-сервисы; DSP-цепочка | ○ | S48 |

**Gapless технически:** у MP3 нет стандартного поля задержки/паддинга кодека → читать **LAME-тег** (или VBRI/Xing), для AAC/M4A — `iTunSMPB` или ISO edit-lists (`elst`); арифметика простая: срезать N отсчётов в начале и M в конце; **разные плееры расходятся** на файлах без тегов ○ S83.

**Копируем:** конвейер *decode → resample → DSP → output*; выход как сменный плагин; WASAPI shared по умолчанию и exclusive опционально; gapless через предоткрытие следующего трека и срезку по LAME/iTunSMPB/elst; ресемплер высокого качества (soxr-класс → у нас `rubato`).
**Адаптация:** устройство тактирует — мы используем event-driven WASAPI; в exclusive-режиме автомикс/EQ/нормализация отключаются (или явно предупреждаем), индикатор «signal path».

## F-02. Нормализация громкости

|---|---|---|---|
| Spotify | **−14 LUFS (Normal)**; пользовательские уровни **Loud −11 / Normal −14 / Quiet −19**; поднимает и опускает; **учитывает альбом** при прослушивании альбома | ○ | S60 |

| Tidal | −14 LUFS, учитывает альбом, в основном опускает | ○ | S60 |
| Amazon Music | −14 LUFS (как Spotify, в пределах лимитов) | ○ | S60 |
| Deezer | −15 LUFS, по треку | ○ | S60 |
| ReplayGain 2.0 | Эталон **−18 LUFS (89 dB SPL)**; теги `REPLAYGAIN_TRACK/ALBUM_GAIN` (смещения) + `*_PEAK`; риск клиппинга при тихих треках → предусилитель/ограничитель | ○ | S61 |

**Адаптация:** по умолчанию **−14 LUFS** с потолком *повышения* +6 dB (как «осторожный Spotify»), понижение — до −12 dB; «Громко» включает лимитер; режим «по альбому» при проигрывании альбома.

## F-04. Приглушение при стороннем звуке (ducking)

**Референсы (6):** Android (Audio Focus) · iOS (AVAudioSession) · Windows (Communications ducking) · Discord (Attenuation) · Google Maps/Waze (запрос transient-duck) · CarPlay/Android Auto.

| Приложение/платформа | Механика | Ур. | Ист. |
|---|---|---|---|
| Android | `AUDIOFOCUS_LOSS_TRANSIENT_CAN_DUCK`: временно потеряли фокус → **снизить громкость**, потом вернуть; с Android O система сама приглушает; **для речи авто-приглушение не применяется** | ✔ | S62 |
| Windows | «Communications»: по умолчанию снижает остальные звуки на **80 %** (варианты: 50 %, mute, не делать) при коммуникационной активности; Win11 — «Adaptive communication sound levels» | ○ | S62 |
| Discord | **Attenuation**: ползунок **0–100 %**, отдельно «когда говорю» / «когда говорят другие» | ○ | S62 |
| iOS | `duckOthers` / `interrupt` — приложение объявляет категорию, система приглушает чужое ◌ | ◌ | — |
| Навигаторы | Короткий голосовой запрос + transient-duck музыки ◌ | ◌ | — |
| `wasapi` crate | Пример `processes` перечисляет **аудио-сессии процессов** (основа для детекта чужого звука) | ✔ | wasapi README |

**Копируем:** семантику «временная потеря фокуса → снизить, затем вернуть», ползунок силы в процентах (Discord), эталон силы 80 % (Windows), исключение речевых уведомлений.
**Отличие/адаптация:** у нас приглушается **сам Сиртон** при активности других сессий (инверсия Discord); детект через Core Audio (`IAudioSessionManager2` + peak meter): активная сессия не из нашего дерева процессов, пик > −60 dBFS ≥ 700 мс; attack 150 мс, hold 1 с, release 1,2 с; сила по умолчанию 75 % (−12 dB).
