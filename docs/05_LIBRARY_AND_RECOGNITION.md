## 1. Нормализация и идентичность

### 1.1. `norm()` — единая функция нормализации (имена артистов, альбомов, названий, запросов)

1. Unicode **NFKC** → **casefold** (полный) → `ё→е`.
2. Диакритика снимается **только у латиницы** (NFD → убрать Mn → NFC); кириллическая «й» сохраняется.
3. `&` → ` and ` (латиница) / ` и ` (если окружение кириллическое); `’ ‘ ‛ ʼ` → `'`; тире/дефисы/подчёркивания/точки/скобки/слэши → пробел.
4. Схлопнуть пробелы, trim. Пустая строка после нормализации → считается «нет значения».
5. Артикли («the ») **не** срезаются в `norm` (только для `sort_name`).

Примеры: `Би-2` → `би 2`; `Би 2` → `би 2` (**автослияние**); `Ёлка` → `елка`; `AC/DC` → `ac dc`; `Beyoncé` → `beyonce`.

### 1.2. Ключи

- `translit_key(s)`: кириллица → латиница по упрощённому ISO 9 (б→b, в→v, ж→zh, х→kh, ц→ts, ч→ch, ш→sh, щ→shch, ю→yu, я→ya, ы→y, э→e, ъ/ь→∅), затем `norm`. `Bi-2` и `Би-2` → `bi 2` ⇒ **предложение** слияния (не автослияние).
- `layout_fix(s)`: карта RU↔EN раскладок (`ghbdtn`↔`привет`) — только для поиска.
- Идентификаторы: `track.uid`/`album.uid`/`artist.uid` — UUID v7; внутри процесса — `i64`.

## 2. Хранилище: шаблоны и санитизация (копия beets + Picard + iTunes, `01b` F-05)

### 2.1. Шаблоны путей (относительно корня библиотеки)

| Случай | Шаблон | Копия у |
|---|---|---|
| Альбом | `{album_artist}/{album}/{disc-}{track:02} - {title}.{ext}` (диск в имени только при `disc_count > 1`: `1-01 - …`) | beets `$albumartist/$album%aunique{}/$track $title`, iTunes |
| Сингл (альбом неизвестен/«single») | `{artist}/Singles/{title}.{ext}` | beets `Non-Album/$artist/$title` |
| Сборник (`Various Artists`) | `Compilations/{album}/{track:02} - {artist} - {title}.{ext}` | beets `Compilations/…`, iTunes |
| Неопознанное | `_Unknown/{исходное имя файла}` | iTunes «Not Added» (идея), наше |
| Одинаковые названия альбомов у исполнителя | суффикс ` (год)` или ` (2)` | beets `%aunique` |

Папка исполнителя — `artist.folder_name` (после санитизации); у фитов физически лежит у **основного** (первого) исполнителя ✅.

### 2.2. Санитизация имён (`sanitize_component`)

Копия набора правил beets `replace` + Picard «Windows compatibility»:

1. `[\\/]` → `_`; `[<>:"?*|]` → `_`; управляющие `0x00–0x1F` → `_`.
2. Ведущая `.` → `_`; конечные `.` и пробелы → удалить; ведущие пробелы → удалить; ведущий `-` → `_`.
3. Зарезервированные имена Windows (`CON PRN AUX NUL COM1–9 LPT1–9`, также с расширением) → суффикс `_`.
4. NFC; максимум **120 символов** на компонент (обрезка по границе графемы), общий путь ≤ **240** (запас до 259 Picard/MAX_PATH; в манифесте `longPathAware`, но проводник и сторонние программы могут не справиться — урок Picard).
5. Коллизии без учёта регистра (NTFS) → ` (2)`, ` (3)`.
6. Неудаляемые символы (эмодзи и пр.) сохраняются, если файловая система принимает (проверка записью тестового имени — для FAT/exFAT).

Все функции покрыты property-тестами (`proptest`): результат всегда валиден на NTFS/exFAT/FAT32, идемпотентен, не пуст.

## 3. Импорт (копия iTunes + beets, `01b` F-06)

### 3.1. Состояния файла

```
Discovered → Probed → Copied(staging) → Identified → Placed → Indexed → [фоновые задачи]
                 ↘ Rejected(причина)  ↘ Duplicate(в отчёт)   ↘ Unknown(причина)
```

1. **Discovered:** Tauri отдаёт пути из drag-drop; рекурсивный обход папок (`jwalk`), фильтр по расширению *и* пробе (магические байты).
2. **Probed:** `symphonia`/`lofty` читают контейнер, кодек, длительность, теги; не аудио или не декодируется → `Rejected` (**в отчёт «Не добавлено» с причиной**, как «Not Added» у iTunes; источник не трогаем).
3. **Copied:** копирование во `staging/<batch>/` потоково, **BLAKE3 считается на лету** (1 МиБ буфер, `FILE_FLAG_SEQUENTIAL_SCAN`), 2–4 файла параллельно (насыщение USB без раздёргивания); временное имя `.part`, затем атомарный `rename`. Источник не изменяется ✅.
4. **Identified:** см. §4 (теги → имя → папка → расстояние → решение).
5. **Placed:** перенос из staging в каноническое место или `_Unknown` через `fs_journal`; **высокая уверенность → сразу в каноническое место; иначе в `_Unknown`** (чтобы не двигать файл дважды).
6. **Indexed:** запись в БД, события `library://changed` (**трек играбелен сразу**); постановка задач: `probe_cover` → `fingerprint` → `lookup_*` → `analyze_basic` → `analyze_deep`.

### 3.2. Отчёт по батчу (`import_batch.report_json`)

Добавлено · В «Неизвестные» (с причинами) · Дубли (3 класса, §6) · Не добавлено (причины: не аудио / повреждён / неподдерживаемый / нет места на диске / слишком длинный путь) · Время · «**Можно извлекать носитель**» (когда все исходные файлы скопированы и хэши сошлись).

### 3.3. Особые случаи

- **Аномально длинные** (> 25 мин, либо > 15 мин при неопознанных): `Unknown(possible_non_track)`; пользователь отмечает «нормальный» (`user_normal=1`) и назначает данные ✅.
- **Нет места на диске:** предварительная оценка по сумме размеров; остановка с понятным сообщением, уже скопированное остаётся валидным.
- **Сбой посреди импорта:** журнал + `.part` чистятся при старте; пакет можно **возобновить** (beets `resume`).
- **Отмена:** уже размещённые остаются, staging чистится.
- **Те же файлы повторно:** по `content_hash` → класс «точная копия» (§6).

## 4. Распознавание (копия beets + Picard, `01b` F-07)

### 4.1. Источники признаков

| Источник | Что даёт | Надёжность |
|---|---|---|
| Теги файла (`lofty`; для WMA — WMF/Property System) | artist, title, album, album_artist, track/disc, year, genre, MBID, ReplayGain | высокая, если **правдоподобны** |
| **Имя файла** по шаблонам | artist, title, track | по ТЗ ✅ надёжнее акустики; зависит от шаблона |
| **Родительские папки** (`…/Артист/Альбом (2019)/…`) | artist, album, year | средняя |
| **Консенсус по папке** (≥ 3 файлов): мода значений | album, album_artist | высокая |
| Отпечаток → AcoustID → MusicBrainz | canonical artist/title/album/year/MBID, cover | высокая (score ≥ 0,9) |
| Аудио-анализ | жанр/настроение (не личность!) | низкая — не используется для личности |

### 4.2. Парсинг тегов и исправление кодировок

- Строка считается **mojibake**, если ≥ 60 % символов в `U+00C0–U+00FF` и нет кириллицы, **или** (D-67) в ней есть целое слово из ≥ 3 букв только из `U+00C0–U+00FF` (смешанные строки «Echo Âåòåð», «AC/DC - Ìîÿ ïåñíÿ»; одиночные акценты «Café», «Björk» — не mojibake): перекодировать `Latin-1 → bytes → cp1251` (затем cp866, koi8-r); принять, если результат ≥ 70 % кириллица и биграммы правдоподобны (`encoding_rs` + `chardetng` как подсказка).
- Мусорные значения: `Unknown`, `Unknown Artist`, `Track 01`, `Audio Track`, `www.…`, `[…]` рекламные, только цифры, «Исполнитель»/«Название» (шаблоны редакторов) → «нет значения».
- Разделение исполнителей — по `ARTISTS` (многозначный) или по разделителям (Navidrome/MusicBrainz): ` feat. `, ` ft. `, ` featuring `, ` & `, `, `, ` x `, ` vs. `, ` / `, ` и `, ` with `; первый — основной.

### 4.3. Парсер имени файла

Предобработка: убрать расширение; `_`→пробел; схлопнуть пробелы; убрать «мусор» в скобках: `[www.…]`, `(Official Video)`, `(Lyrics)`, `(HD)`, `[320kbps]`, ` - Topic`, `(Audio)`; **версии оставляем** в названии: `(Remix)`, `(Live)`, `(Acoustic)`, `(Radio Edit)`.

Шаблоны в порядке приоритета (разделитель — **только пробел-тире-пробел** `\s[-–—−]\s`, чтобы не ломать `Би-2`, `Jay-Z`, `AC-DC`):

| № | Шаблон | Извлекает |
|---|---|---|
| 1 | `^(\d{1,3})[.\s)\-_]+(.+?)\s[-–—]\s(.+)$` | track, artist, title |
| 2 | `^(.+?)\s[-–—]\s(.+)$` | artist, title |
| 3 | `^(\d{1,3})[.\s)\-_]+(.+)$` | track, title (artist — из папки/тегов) |
| 4 | `^(.+)$` | title |

Многозначность («A - B - C»): сначала проверка по **словарю артистов библиотеки** (известный префикс); иначе левая часть — артист. Уверенность шаблона: 1 > 2 > 3 > 4 = 0,9 / 0,8 / 0,5 / 0,3 (корректируется совпадением с папкой).

### 4.4. Расстояние кандидата (копия beets: взвешенная сумма + 3 зоны)

Для кандидата (запись MusicBrainz из AcoustID **или** «собственный» из тегов+имени+папки) считается взвешенное нормированное расстояние `d ∈ [0,1]` по **доступным** компонентам:

| Компонент | Вес | Метрика (0 = совпало) |
|---|---|---|
| `acoustid_score` | 5,0 | `1 − score` |
| `mb_recording_id` в тегах | 5,0 | 0 если равны, 1 если иные |
| `artist` | 3,0 | 1 − token-set ratio (Damerau–Levenshtein по `norm`), по лучшему из исполнителей |
| `title` | 3,0 | то же |
| `album` | 3,0 | то же, если альбом известен локально |
| `length` | 2,0 | 0 при \|Δ\| ≤ **2 с** (допуск Picard), линейно до 1 при ≥ 10 с |
| `track_no` | 1,0 | 0/1 |
| `year` | 1,0 | 0 при равенстве, 0,5 при ±1, иначе 1 |

`d = Σ wᵢdᵢ / Σ wᵢ` (только присутствующие компоненты; если их < 3 — зона «strong» запрещена).

**Зоны (значения в `config/recognition.toml`, калибруются на золотом наборе; стартовые):**

| Зона | Условие | Действие |
|---|---|---|
| **strong** | `d ≤ 0,06` и ≥ 3 компонента (и `acoustid_score ≥ 0,9`, если кандидат онлайн) | автоприменение (beets: `strong_rec_thresh` = 0,04) |
| **medium** | `d ≤ 0,25` | подсказка пользователю в «Неизвестных» (не применять) |
| **none** | иначе | **пропуск = «Неизвестные»** (beets `quiet_fallback: skip`) ✅ |

### 4.5. Таблица решений (теги T, имя F, папка P, онлайн O)

| № | Ситуация | Решение |
|---|---|---|
| 1 | T и F согласуются (sim ≥ 0,9) | strong → размещение по тегам; онлайн только дозаполняет (год, обложка) |
| 2 | Только T (имя не информативно: `Track 01`) | strong, если есть artist+title+album+№; иначе medium → `confirmed` позже по O; до этого разместить, если T полны |
| 3 | Только F, теги пусты | если F+P согласуются → strong; иначе → `Unknown(no_metadata)` до O |
| 4 | T и F конфликтуют | офлайн → `Unknown(conflict)` с двумя кандидатами; онлайн → побеждает кандидат, подтверждённый O |
| 5 | O strong (score ≥ 0,9), T/F согласны | canonical-написание из MB; исправление опечаток **только** если правка мала (≤ 3 символа/JW ≥ 0,85) |
| 6 | O strong, T/F нет | размещение по MB |
| 7 | O strong, T/F резко расходятся | доверять O при `score ≥ 0,95` и \|Δ длительности\| ≤ 2 с; иначе → `Unknown(conflict)` |
| 8 | O слабый (0,5 ≤ score < 0,85) | только подсказка |
| 9 | Нет данных, офлайн | `Unknown(offline_pending)`; задача `resolve_unknown` при появлении сети ✅ |
| 10 | Очень длинный | `Unknown(possible_non_track)` ✅ |

### 4.6. Онлайн-распознавание (AcoustID → MusicBrainz → CAA)

1. `fingerprint`: декод первых 120 с → Chromaprint (`rusty-chromaprint` 0.3; 🧪 паритет с `fpcalc` на корпусе, спайк S-06) → в БД.
2. `GET api.acoustid.org/v2/lookup?client=<ключ>&duration=<сек>&fingerprint=<fp>&meta=recordings+releasegroups+compress` (≤ 2 запр/с; **ключ приложения** — ❓OWN-02). Кандидаты `score ≥ 0,85`.
3. При нехватке данных (альбом/год/№): `GET musicbrainz.org/ws/2/recording/<mbid>?inc=artists+releases+release-groups+genres&fmt=json` (≤ 0,8 запр/с; `User-Agent: SirTone/<ver> ( <контакт> )` ❓OWN-03).
4. **Выбор релиза:** (a) совпавший с локальным альбомом/консенсусом папки; (b) иначе самый ранний *официальный* релиз-группы типа Album без вторичных типов Compilation/Live/Soundtrack; (c) иначе сингл → `Singles`.
5. Обложка: `coverartarchive.org/release-group/<mbid>/front-500` (редирект на archive.org).
6. Кэш всех ответов в `http_cache` (MB 30 дн., CAA 90 дн., AcoustID 90 дн.).

### 4.7. «Неизвестные» (копия Picard Unmatched / iTunes Not Added / WaveFlow Needs attention, `01b` F-08)

- Поля: `unknown_reason` ∈ {`no_metadata`, `conflict`, `low_confidence`, `offline_pending`, `possible_non_track`, `needs_review`} + `candidates_json` (до 3 кандидатов с `d` и источниками).
- Действия: принять кандидата (1 клик) · ввести вручную · перетащить к исполнителю/альбому · «нормальный» (для длинных) · повторить онлайн · удалить (в Корзину). Групповые операции по причине.
- **Фоновое доопределение** при появлении сети ✅: `resolve_unknown` (приоритет 38) → при strong → `relocate_track` → событие.

### 4.8. Настроение/жанр по соседям (ТЗ 7.3.5)

Приор `Prior(mood | artist/folder)` — Дирихле по размеченным трекам исполнителя/папки; сила ~ `log(1 + n)`; финал: `posterior ∝ P(audio)·Prior`, применяется при `posterior ≥ τ` (`04` §10.3). Жанр: теги → онлайн (MB genres) → модель (только при высокой уверенности).

## 6. Дубли (копия SongKong + dupeGuru + beets, `01b` F-09)

| Класс | Критерий | Действие по умолчанию |
|---|---|---|
| **Точная копия** | равный `content_hash` | не добавлять новый |
| **Тот же звук** | отпечатки: схожесть ≥ 0,92 на ≥ 80 % перекрытия и \|Δ длительности\| ≤ 3 с (разный кодек/битрейт/теги) | показать пару, предложить «заменить» при лучшем качестве (lossless > lossy > битрейт) |
| **Похожий (другая версия)** | схожесть 0,75–0,92 или равные `norm(artist, title)` при разном звуке (ремикс/live) | оставить оба |

- **Поиск кандидатов:** окно длительности ±3 с (индекс `ix_track_dur`) → сравнение отпечатков (XOR+popcount по сдвигам, `match_fingerprints` из `rusty-chromaprint`); цена — десятки сравнений на новый трек; порог/класс — 🧪 S-06.
- **Решение по каждому ✅:** оставить оба · заменить старый новым · не добавлять новый (beets: skip/keep/remove/merge). **Заменить** = новый файл становится треком: переносятся `play_count`, `last_played_at`, членство в плейлистах, ручные правки; старый файл → Корзина (через журнал).
- Отчёт: «уже есть», «новый», «похожи, но названия разные» ✅.

## 7. Слежение за файлами (копия Navidrome + Plex, `01b` F-11)

- **Watcher:** `notify` (ReadDirectoryChangesW) по корню, дебаунс 500 мс, игнор `.sirtone/`, `*.part`; события → очередь `reconcile_fs`. **При старте** — быстрая сверка `(rel_path, size, mtime)` с БД через `jwalk` (50 000 файлов ≈ 2–4 с, в фоне после показа UI).
- **Обнаружение перемещений:** исчез файл + появился новый с тем же **NTFS FileId**, а на exFAT/FAT — `(size, BLAKE3 первых/последних 64 КБ)` с подтверждением полным хэшем → обновить `rel_path`, **сохранив статистику и плейлисты** (Navidrome).
- **Состояние `missing`:** файл пропал, замены нет, **корень доступен** → `state='missing'` (скрыт из списков), запись **тихо удаляется через 24 ч** ✅; вернулся — снова `ok`.
- **Корень недоступен** (флешка вынута, сетевой путь) → библиотека «офлайн», **ничего не помечаем и не удаляем** (защита Plex/Navidrome).
- **Неоднозначные ситуации → вопрос пользователю:** пропало > 20 % библиотеки или > 200 файлов за один проход; найдены кандидаты-перемещения вне корня; переименована корневая папка («Указать новое место?»).
- **Внешние добавления** (вопрос 9 ✅ 🔧): принимаются «на месте» (идентичность выводится из пути), запускается стандартный конвейер; если каноническое место отличается — **предложение** «Навести порядок?» (по умолчанию не двигать молча; настройка `organize_external: suggest|auto|never`).
- **Журнал:** все перемещения — через `fs_journal`; незавершённое при старте откатывается/доводится.

## 8. Плейлисты (копия Navidrome `.nsp` + Apple, `01b` F-13, F-14)

### 8.1. Умные плейлисты — схема правил (`rules_json`)

```jsonc
{
  "all": [                                  // или "any"; допускаются вложенные группы (но не all и any на одном уровне)
    { "inTheLast": { "added_at": 30 } },    // операторы: is, isNot, gt, lt, contains, notContains, startsWith, endsWith,
    { "gt": { "energy": 0.6 } },            //   inTheRange, before, after, inTheLast, notInTheLast, inPlaylist, notInPlaylist,
    { "is": { "lang": "none" } },           //   isMissing, isPresent
    { "any": [ { "is": { "mood": "sad" } }, { "gt": { "arousal": 0.7 } } ] }
  ],
  "sort": "-last_played",                   // несколько полей через запятую, + / - ; "random" допустим
  "limit": 100,                             // либо "limit_minutes", "limit_mb" (Apple)
  "limitPercent": 20,
  "refresh": "live"                         // live (Apple "Live updating") | "12h" | "manual" (Navidrome refreshDelay)
}
```

- **Поля (белый список → безопасный SQL):** `title, artist, album, genre, year, added_at, last_played, play_count, skip_count, favorite_score, duration, bitrate, lossless, format, size, bpm, key, energy, valence, arousal, danceability, acousticness, vocal, lang, mood, activity, identity_state, path` + `in_playlist` + (1.3) `liked`, `familiarity` (любимое/знакомое/забытое/новое/нетронутое, `14` §9), `season_tag`, `explicit`.
- Смарт-плейлист **нельзя править вручную** (Apple) — есть «Сохранить как обычный» (снимок); «живое» обновление при `library://changed` или по `refresh`.

### 8.2. Гибридные / продолжение

Алгоритм — `04` §11. Интерфейс: после последнего «моего» трека — разделитель «Рекомендовано из вашей медиатеки», на каждом рекомендованном «+» и «−»; общий тумблер ∞ в очереди (Apple/YouTube Music/Roon); по умолчанию включён для **ручных плейлистов**, выключен для **альбомов**.

### 8.3. Очередь

Контекст (альбом/плейлист/волна/поиск) + явные «играть следующим/в конец». Запуск трека из другого контекста **заменяет** очередь ✅. История «назад» — на сессию. Повтор: выкл/трек/контекст. Шафл — `04` §11.

## 9. Поиск (`01b` F-17)

1. **Нормализация запроса:** `norm`, `layout_fix`, транслитерация в обе стороны, морфология (Snowball RU/EN — `rust-stemmers`), стоп-слова.
2. **Лексический поиск:** FTS5 `search_fts` (префикс `токен*`, bm25: `title 4, artists 5, album 2, genre 1, aliases 1`), если < 5 результатов — **триграммы** `search_tri` (устойчивость к опечаткам), затем перерасчёт Damerau–Levenshtein ≤ 2 для токенов ≥ 5 символов на топ-200; бусты: префикс первого слова ×1,5, точное совпадение названия ×2, `log(1+play_count)`.
3. **Смысловой разбор:** лексикон `assets/lexicon/ru.json|en.json` → фасеты. Пример записей:

```jsonc
{ "грустн": {"facet":"valence","op":"lt","value":0.35,"w":1.0},
  "печальн": {"facet":"valence","op":"lt","value":0.35,"w":0.9},
  "медленн": {"facet":"bpm","op":"lt","value":90,"w":1.0},
  "спокойн": {"facet":"arousal","op":"lt","value":0.35,"w":1.0},

  "бодр": {"facet":"mood","value":"upbeat","w":1.0},
  "без слов": {"facet":"vocal","op":"lt","value":0.3,"w":1.0},
  "для сна": {"facet":"activity","value":"sleep","w":1.0},
  "для работы": {"facet":"activity","value":"work","w":1.0},
  "для тренировки": {"facet":"activity","value":"workout","w":1.0},
  "дождь": {"facet":"atmosphere","value":"rain","w":0.6},

```

   Запрос «что-то грустное и медленное» → стоп-слова убраны → фасеты `valence<0.35`, `bpm<90` → результаты по произведению мягких принадлежностей + кнопка «**Играть этот вайб**» (запуск волны с этими фасетами). Пользовательские синонимы можно расширять.

## 10. «Моя волна» и контекст (копия Яндекс «Моя волна» + Spotify daylist, `01b` F-18, F-19)

### 10.1. Запрос волны

`WaveQuery = { profile, mood[], character[], language[], frequency[], activity[], workout_tempo?, atmosphere{auto|manual, daypart?, weather?}, season{auto|winter|spring|summer|autumn|off}, events[], novelty, influence{season, context, events}, energy_range?, tempo_range? }` — фильтры **комбинируются** ✅; это слой 3 движка волны (`14` §1), новые поля — дополнение §27 (FR-LEARN-011).

- **Жёсткие:** `language`, `frequency` (если выбраны; при выбранной `frequency` ползунок новизны неактивен — D-42), `energy_range`, `tempo_range`.
- **Мягкие** (функции принадлежности из `04` §10.2): `mood`, `character`, `activity`, `atmosphere` → компонент `filters` скоринга (`14` §6): `Π membershipᵢ^wᵢ`.
- **Ослабление** при нехватке (< 30 треков со `score ≥ 0,5`): по `relax_order` профиля, по умолчанию расширяем σ мягких критериев в порядке atmosphere → activity → character → mood; жёсткие фильтры пользователя снимаем в последнюю очередь, жёсткие фильтры режима — никогда; пользователю — «**Мало треков — расширил подбор**» ✅ (FR-WAVE-006).
- **Частота** (согласовано с категориями ползунка, `14` §9): `любимые` — категория «Любимое» (лайк или ≥ 8 прослушиваний и высокая оценка; при пустом — топ 10 % по `fav_score = 0,6·ln(1+plays) + 0,4·completion_ema − 0,5·skip_ratio` с полураспадом 180 дн.); `часто слушаю` — ≥ 3 прослушиваний за 30 дн. (по `plays_recent`); `забытые` — `plays ≥ 3` и последнее прослушивание **> 60 дн.** (было 90; приведено к дополнению §34 и Spotify Repeat Rewind).
- **Темп для тренировки** (Яндекс): лёгкий 110–130, средний 130–160, интенсивный 160–185 BPM.
- Генератор потока — движок волны (`14` §6–7).

### 10.2. Контекст

| Сигнал | Источник | Без сети |
|---|---|---|

## 11. Статистика прослушиваний (`01b` F-20)
